# Phase 182.1: ZIP Centroid Mapping for Unique/PO-Box and Placeholder ZIPs — Context

**Gathered:** 2026-10-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Recover distances for the 134,949 `zip_not_in_db` encounters left after Phase 182 by:
(a) crosswalking unique/campus and PO-box facility ZIPs (32610, 32611, 32614, 33242, …) to ZCTA
    via the HRSA UDS Mapper crosswalk, then resolving centroids from the ZCTA gazetteer;
(b) marking placeholder facility ZIPs (000xx; ZIP3+"00" codes not present in the crosswalk)
    as missing so the Phase 182 FACILITYID fill can recover them;
(c) re-running R/122 → R/165 → R/179 → R/180 → R/181 with explicit RDS overrides;
(d) producing a single old-vs-new comparison table (R/165, R/179, R/180 D-05/D-09, R/181)
    in an extended 182.1 report so the team can decide on a memo update.

Fix scope: new `R/utils/utils_zip_crosswalk.R`; R/122 modified (placeholder step + fallback
orchestration + `distance_method` column); R/165 gains `R165_R122_RDS` override; R/182
report extended for 182.1 before/after comparison. No new pipeline script; no hand-coded
ZIP mappings; no changes to patient-side sentinel logic.

</domain>

<decisions>
## Implementation Decisions

### Crosswalk Source and Staging
- **D-01:** HRSA UDS Mapper "ZIP Code to ZCTA Crosswalk" (latest available year) staged
  manually by the user into `data/reference/` on HiPerGator. Path registered in CONFIG
  (e.g., `CONFIG$hrsa_zip_zcta_path`). Script stops with a clear message if the file is
  absent. No hand-coded ZIP→ZCTA mappings under any circumstances.
- **D-02:** File name and vintage year are recorded in the KEY sheet of every workbook
  produced by this phase (R/122 xlsx, 182.1 report).
- **D-03:** ZCTA gazetteer (`data/reference/zcta_gazetteer_centroids.csv`) is already
  staged on HiPerGator. It is tab-delimited despite the `.csv` extension; read with
  `read.delim(..., sep = "\t")`. Required columns: `GEOID`, `INTPTLAT`, `INTPTLONG`.
  The CONFIG path `CONFIG$zcta_gazetteer_path` and `.load_zcta_gazetteer()` in
  `utils_address.R` are already wired — no changes to that loader.

### New Helper: `utils_zip_crosswalk.R`
- **D-04:** New file `R/utils/utils_zip_crosswalk.R` with two pure functions:
  - `map_zip_to_zcta(zip5, xwalk)` — looks up zip5 in the HRSA crosswalk table;
    returns the corresponding ZCTA or `NA` if not found.
  - `is_placeholder_facility_zip5(zip5, xwalk)` — returns `TRUE` for 000xx patterns
    AND for ZIP3+"00" codes (32800, 32700, 34700, …) that are absent from the
    crosswalk (i.e., not real delivery ZIPs). Takes the crosswalk to avoid
    hard-coding the list of ZIP3+"00" values.
- **D-05:** `is_sentinel_zip5()` in `utils_address.R` is NOT modified. It is used
  on the patient side in R/120/R/121 and touching it would shift locked
  reconciliation constants. Placeholder detection for facility ZIPs is entirely
  separate and lives only in `utils_zip_crosswalk.R`.

### R/122 Orchestration
- **D-06:** Placeholder step runs in R/122 **before** the Phase 182 FACILITYID fill,
  so facility ZIPs identified as placeholders become candidates for the donor fill
  rather than being silently excluded from it.
- **D-07:** Distance fallback tiers (facility-side, for `zip_not_in_db` pairs only):
  1. `zipcodeR_raw` — existing `zip_distance()` call (unchanged, canonical per Phase 152).
  2. `zipcodeR_crosswalk` — if `zip_distance()` returns `NA`, crosswalk the facility
     ZIP to ZCTA via HRSA and retry `zip_distance()` on the ZCTA.
  3. `haversine_gazetteer` — if still `NA`, compute haversine from gazetteer centroids
     (already in `utils_address.R`).
  zipcodeR distances for encounters that already resolve are never changed.
- **D-08:** `distance_method` column added to the R/122 RDS per encounter:
  `zipcodeR_raw` / `zipcodeR_crosswalk` / `haversine_gazetteer` / `NA` (unresolved).
  Stored in the RDS and summarised in the R/122 KEY sheet.
- **D-09:** R/122 writes a new dated RDS (e.g., `output/encounter_distance_<YYYYMMDD>.rds`).
  The Phase 182 RDS (`output/encounter_distance_20261014.rds`) is never overwritten.
- **D-10:** The false "zipcodeR coverage gap" sentence in 182-RECOVERY.md is removed;
  replaced with the actual finding from the Phase 182 C_zip_not_in_db sheet.
  (182-RECOVERY.md lives in `output/`; the committed copy in the phase dir is untouched.)

### R/165 Re-Run
- **D-11:** Add `R165_R122_RDS` override to R/165 (same pattern as `R179_R122_RDS`).
  When set, R/165 reads that RDS instead of auto-picking the most recent by mtime.
- **D-12:** R/165 run method: interactive R in a compute-node session (`salloc`) with
  sufficient memory — same as R/122. "Do not run interactively" in R/165's header means
  not on a login node; a compute-node salloc session is fine.
- **D-13:** R/165 writes a new dated workbook. The prior
  `output/distance_cbc_association_20261008.xlsx` is never overwritten.

### Re-Run Chain
- **D-14:** Full chain: R/122 → R/165 → R/179 → R/180 → R/181, each with explicit
  RDS overrides. Same `source(f, local = new.env(parent = globalenv()))` convention.
- **D-15:** R/181 writes a new dated workbook and its auto-generated memo to `output/`.
  The committed `181-MEMO.md` in `.planning/phases/181-*/` is never touched.
- **D-16:** All pinned paths for the 182.1 re-run are recorded in the 182.1 report
  (extended from R/182's report pattern).

### 182.1 Report
- **D-17:** No separate R/182.1_*.R pipeline script. R/182's existing
  `R/182_facility_zip_recovery_report.R` is extended (or a thin 182.1 section added)
  to produce the before/after comparison.
- **D-18:** The report shows a single old-vs-new comparison table covering:
  R/165 OR (whole-record and post-anchor), R/179 primary OR, R/180 D-05/D-09 bounds
  and capture-check %, R/181 prior-year CBC × far OR. "Old" = Phase 182 pinned outputs
  (20261014 workbooks); "new" = 182.1 outputs. All values read from workbooks by exact
  label at runtime (not hard-coded).
- **D-19:** Remaining missing-exposure count for Phase 183 (facility_zip_missing +
  unresolved zip_not_in_db after crosswalk) reported in the 182.1 report.
- **D-20:** Team update decision (revised memo to Erin/Ray) deferred until the
  old-vs-new table is in hand. No revised memo produced in this phase.

### Execution Convention
- **D-21:** Interactive R on HiPerGator compute node (`salloc`), `module load R/4.5`,
  `source(f, local = new.env(parent = globalenv()))` for each script in chain.
- **D-22:** Register `utils_zip_crosswalk.R` in SCRIPT_INDEX. R/122.1 changes tracked
