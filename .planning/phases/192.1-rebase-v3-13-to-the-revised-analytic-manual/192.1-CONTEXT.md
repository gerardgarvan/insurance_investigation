# Phase 192.1: Autoimmune Diagnosis Flags in Gantt Episodes - Context

**Gathered:** 2026-10-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Add two new patient-level columns to all Gantt episode datasets — `has_autoimmune_dx` (boolean) and `first_autoimmune_dx_date` (date) — for a specified set of autoimmune ICD-10 (and ICD-9 equivalent) codes. The flag and date are derived from a DIAGNOSIS table pull using the same level, date expression, sentinel handling, and DX_TYPE-gating pattern as the existing HL diagnosis columns in the Gantt build scripts. No existing columns or rows change; row counts are byte-identical to the current output on all existing columns.

Scope:
- `gantt_episodes_90.csv` and `gantt_episodes_180.csv` (plus their `_detail_` counterparts)
- Any derived subset outputs (e.g., NHL/HL+NHL subsets) that carry the same column schema
- `R/170` conditional re-pin after column-parity check
- `R/88` structural checks for the two new columns
- HiPerGator run to confirm real-data counts

Out of scope: any change to existing columns or rows, changes to AM-DRAFT.md or Phase 193 artifacts, pipeline code other than Gantt build scripts and R/00_config.R.

</domain>

<decisions>
## Implementation Decisions

### Code set

- **D-01:** The autoimmune code set is held as one named list constant in `R/00_config.R` Section 4c, next to `RITUXIMAB_CODES`/`MTX_CODES`/`DOI_CODE_MAP`. Name: `AUTOIMMUNE_DX_CODES` (or follow the naming convention for the adjacent constants — planner confirms).
- **D-02:** ICD-10 prefix matches (TRIM, dots removed before matching): M05*, M06*, M31.3, M31.7, L10.0, M08.3*, M08.09, M08.00, L40*. M31.3C3 in the original request was read as M31.3 (prefix family). Confirm M31.3 is correct — do not match M31.3C3 exactly.
- **D-03:** ICD-9 equivalents are included using DX_TYPE-gated prefix matching, exactly as `is_doi_code()` in `utils_doi.R` gates on DX_TYPE before prefix matching. The planner derives the ICD-9 equivalents for each category from the existing `DOI_CODE_MAP` ICD-9 entries (RA 714.x, psoriasis 696.x, SLE 710.x, etc.) and documents them in the constant with per-code comments. Never mix ICD-9 and ICD-10 prefixes in one undifferentiated lookup.
- **D-04:** DX_TYPE matching tolerates format variants: trim whitespace, treat any value that starts with "10" (after trim) as ICD-10, and any value that starts with "09" as ICD-9. Mirror the existing `is_doi_code()` defensive pattern.

### Level and date rule

- **D-05:** Mirror the existing HL diagnosis flag and date columns exactly — same level (patient vs episode), same date expression, same date-range and sentinel handling. **Planner locates the exact HL column rule in `R/52_gantt_v2_export.R` and `R/142_gantt_180_export.R` first and records the rule (with file:line) in the plan before implementing.** Default expectation (from codebase scout): patient-level values from `confirmed_hl_cohort.rds` using `first_hl_dx_date`, with 1910-01-01 sentinel cutoff inherited from Phase 17 / `SENTINEL_CUTOFF`. One value per patient, same on all episode rows including the HL Diagnosis pseudo-rows.
- **D-06:** Column names: `has_autoimmune_dx` (logical, TRUE/FALSE, no NA) and `first_autoimmune_dx_date` (Date, NA when `has_autoimmune_dx` is FALSE).
- **D-07:** The patient-level `first_autoimmune_dx_date` uses `COALESCE(DX_DATE, ADMIT_DATE)` — earliest non-null date across all matching codes for that patient, subject to the same sentinel-exclusion rule as `first_hl_dx_date`. If neither date is available, exclude that record from the "earliest" computation (do not use 1900-01-01 as a date).

### Row-count invariant

- **D-08:** Adding the two columns must not change the row count of any Gantt output. Before/after comparison must confirm: same `(patient_id, episode_number)` key set, same existing column values, zero new rows, zero dropped rows. Record the comparison result in the SUMMARY.

### R/170 pin (conditional re-pin)

- **D-09:** After the new `gantt_episodes_180.csv` is built:
  1. Compare it with the 2026-08-14 `_PINNED` snapshot on original columns only (same rows, same keys, same values). Record the result in SUMMARY.
  2. **If identical on original columns:** save a new `_PINNED` copy, update `CONFIG$gantt_180_snapshot_path`, `_bytes`, and `_md5`; keep the old path commented with its date; update the hard-coded byte-count label in R/170's KEY/QC sheet.
  3. **If not identical:** keep the 2026-08-14 pin. Since the new flag/date are patient-level, add them to R/170's output by joining on `patient_id` from the new build rather than re-running from the pinned file.
  4. Confirm which Gantt version the chemo-combos workbook (NHL subsets) was built from — its `episode_number` keys must match whichever snapshot R/170 uses.

### R/88 and registration

- **D-10:** Add structural checks in R/88 for the two new columns: existence in gantt_episodes and gantt_episodes_180 (column name check), correct type (logical + Date), no all-NA values (at least one TRUE in `has_autoimmune_dx` is expected with real data — gate this check with IS_LOCAL).
- **D-11:** The `AUTOIMMUNE_DX_CODES` constant appears in R/88's config-existence checks alongside `RITUXIMAB_CODES` and `MTX_CODES`.

### HiPerGator

- **D-12:** Real run on HiPerGator required. Record in SUMMARY: count of patients with `has_autoimmune_dx == TRUE`, count of distinct autoimmune codes observed, and confirmation that row counts match the pre-phase baselines. No counts 1–10 in any shared output.

### Claude's Discretion

- Exact section placement of the new R/88 checks (append to existing Section 15w/15x or open a new section).
- Whether to add a helper function (e.g., `is_autoimmune_code()`) in `utils_doi.R` or inline the prefix logic in the Gantt build scripts.

</decisions>

### Reusable Assets

### Established Patterns
- Gantt build scripts add patient-level columns via left-join from a pre-computed patient-grain tibble (load cohort RDS → select(ID, date_col) → filter(!is.na()) → join onto episode rows)

- `_PINNED` snapshot pattern in R/00_config.R: path + _bytes + _md5 keys, old path commented with date
