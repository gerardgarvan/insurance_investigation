<domain>
## Phase Boundary

Add two patient-level columns to every Gantt episode output — `has_autoimmune_dx` (logical) and `first_autoimmune_dx_date` (Date) — for a defined set of autoimmune diagnosis codes, mirroring the existing HL diagnosis flag/date columns. Existing rows and columns are unchanged: same row count, same original columns in the same order, same values (verified per D-08).

**Files this phase may modify:** `R/00_config.R`, `R/utils/utils_doi.R` (helper), the Gantt build scripts (`R/52_gantt_v2_export.R`, `R/142_gantt_180_export.R`, and any other script found in the D-13 inventory that writes a Gantt episode output), `R/170_nhl_gantt_subsets.R` (D-09), `R/88_smoke_test_comprehensive.R` (D-10), tests under `tests/testthat/`, `R/SCRIPT_INDEX.md`.

Out of scope: any change to existing columns or rows; AM-DRAFT.md and Phase 193 artifacts (handled in Phase 192.2); any other pipeline script.

</domain>

<decisions>
## Implementation Decisions

### Code set

- **D-01:** One named constant in `R/00_config.R` Section 4c, next to `RITUXIMAB_CODES` / `MTX_CODES` / `DOI_CODE_MAP`, following their naming convention (default `AUTOIMMUNE_DX_CODES`). Structure: separate `icd10` and `icd9` vectors, each entry with a comment naming the condition. ICD-9 and ICD-10 prefixes are never mixed in one lookup.
- **D-02 (ICD-10, prefix match after TRIM and dot removal):** M05, M06, M313, M317, L100, M083, M0809, M0800, L40.
  - Families: M05*, M06*, L40*, M31.3* (= M31.30, M31.31).
  - Terminal codes (prefix match is effectively exact): M31.7, L10.0, M08.3, M08.09, M08.00.
  - "M31.3C3" in the original request is not a valid ICD-10-CM code; it is read as M31.3. Recorded as an assumption for team confirmation in Phase 194.
- **D-03 (ICD-9, explicit mapping — not derived wholesale from `DOI_CODE_MAP`):** one entry per ICD-10 family above, chosen to match the ICD-10 definition as narrowly as ICD-9 allows, each verified against the CMS ICD-10/ICD-9 General Equivalence Mappings and recorded with its GEM source in a mapping table in the plan. Proposed starting point (to verify, not to adopt unchecked):
  | ICD-10 family | Proposed ICD-9 | Note |
  |---|---|---|
  | M05*, M06* (RA) | 714.0, 714.1, 714.2 | 714.3x is juvenile; 714.4+ other arthropathies — exclude |
  | M08.3, M08.09, M08.00 (juvenile) | 714.30, 714.31, 714.32, 714.33 as GEM maps them | map each terminal code individually |
  | M31.3 (GPA) | 446.4 | |
  | M31.7 (microscopic polyangiitis) | per GEM (446.0 is broader polyarteritis nodosa — flag if used) | |
  | L10.0 (pemphigus vulgaris) | 694.4 | 694.4 covers all pemphigus (broader than L10.0) — flag as broader |
  | L40* (psoriasis) | 696.0, 696.1, and 696.8 only if GEM maps it to L40 | 696.2–696.5 are parapsoriasis/pityriasis (L41–L44) — exclude |
  Any ICD-9 code broader than its ICD-10 counterpart is marked `broader` in the constant's comment and reported separately in QC. SLE is not in scope (no ICD-10 SLE code was requested).
- **D-04:** Before implementing, tabulate the actual DX_TYPE values in DIAGNOSIS for cohort patients and record them. Accepted values are listed explicitly from that tabulation (expected: variants of "10" and "09" after trim); all other values are excluded and counted in QC. Gate on DX_TYPE before prefix matching, as `is_doi_code()` does.

### Diagnosis source and aggregation

- **D-05 (mirror rule):** First locate the HL flag/date columns in the Gantt build scripts and record their exact rule (file:line): level, date expression, date-range filter, sentinel handling, and whether the date comes from a cohort RDS. The autoimmune columns mirror that rule. Expected (to confirm): patient-level, one value per patient repeated on every row including HL pseudo-rows; sentinel `SENTINEL_CUTOFF` (1910-01-01) from config.
- **D-05a:** Source = DuckDB `DIAGNOSIS` for cohort patients, whole extract unless the HL rule applies a date-range filter, in which case the same filter applies. Patient-level by design: a diagnosis dated after an episode still sets the flag on that patient's earlier episodes; "before this episode" is derivable as `first_autoimmune_dx_date <= episode_start`.
- **D-05b:** Aggregate to exactly one row per `ID` before joining (assert `nrow == n_distinct(ID)`); duplicate diagnosis records collapse in the aggregation. Join by left join on the patient key; assert output row count equals input row count immediately after the join.

### Flag and date semantics

- **D-06:** `has_autoimmune_dx` (logical, never NA) and `first_autoimmune_dx_date` (Date).
- **D-07 (date):** per diagnosis record, valid date = `DX_DATE` if non-null and after the sentinel, else `ADMIT_DATE` if non-null and after the sentinel, else no valid date (invalid values are excluded before falling back, not after). Patient date = minimum valid date across qualifying records. If the HL rule orders these steps differently, mirror the HL rule and record it.
- **D-07a (flag):** `has_autoimmune_dx = TRUE` if and only if `first_autoimmune_dx_date` is non-NA. Patients with a qualifying code but no valid date get FALSE/NA and are counted in QC as "qualifying code, no valid date". Invariant asserted in code and R/88: no TRUE with NA date, no FALSE with a date.

### Output inventory and regression check

- **D-13:** Inventory every output that carries the Gantt episode schema before changing code: `gantt_episodes` (90-day) and `gantt_episodes_180`, their `_detail_` versions, R/170 outputs, and any other script that reads or writes these files (grep `gantt_episodes`). Record the list; every listed output gets the two columns or is explicitly excluded with a reason.
- **D-14:** Before modifying code, save the current outputs as baselines (`*_PRE1921.csv`, in output/internal).
- **D-08 (multiplicity-aware comparison, per output):**
  1. Row counts equal.
  2. Original column names and order unchanged; the two new columns appended at the end.
  3. Original columns compared row by row as complete rows, preserving duplicates (sorted multiset comparison), with types parsed explicitly from the CSV.
  4. `(patient_id, episode_number, treatment_type)` key multiplicities unchanged.
  5. Serialization: dates written as ISO `YYYY-MM-DD`, NA written the same way existing columns write it, logical as TRUE/FALSE.
  Results recorded in the SUMMARY. Any difference stops the phase.

### R/170 pin (conditional)

- **D-09:**
  1. Compare the new `gantt_episodes_180` with the 2026-08-14 pinned snapshot on original columns per D-08 steps 1–4.
  2. Identical → save a new `_PINNED` copy; update `CONFIG$gantt_180_snapshot_path`, `_bytes`, `_md5`; keep the old path commented with its date; update the hard-coded byte-count label in R/170's KEY/QC.
  3. Not identical → keep the 2026-08-14 pin and add the two columns to R/170's outputs by joining on `patient_id` from the new build (one row per patient, asserted).
  4. Before choosing, confirm which Gantt version the current chemo-combos workbook was built from and check its `(patient_id, episode_number)` keys against the snapshot R/170 will use: join cardinality and unmatched counts recorded.

### R/88 and tests

- **D-10:** R/88 checks: both columns present in each inventoried output; parsed types (logical, Date) after explicit `col_types`; flag/date invariant (D-07a); constant present in config alongside `RITUXIMAB_CODES`/`MTX_CODES`; at least one TRUE on real data (gated by `IS_LOCAL`).
- **D-15:** testthat fixtures (run on HiPerGator; no local Rscript) for: no qualifying dx → FALSE/NA; one ICD-10 dx → TRUE/date; one ICD-9 dx → TRUE; qualifying code with wrong DX_TYPE → no match; multiple dates → earliest; sentinel-only or undated → FALSE/NA; DX_DATE invalid with valid ADMIT_DATE → ADMIT_DATE used; multiple episodes → identical values per patient; duplicate dx records → no row multiplication; terminal code with an unexpected suffix (e.g., M3170X) handled per the prefix rule and noted.

### HiPerGator

- **D-12:** Run interactively (`module load R/4.5`, `R`, `here::i_am("R/00_config.R")`, source the scripts). SUMMARY records: patients with TRUE, distinct codes observed by ICD-9/ICD-10, patients matched only via `broader` ICD-9 codes, qualifying-code-no-valid-date count, D-08 results, D-09 branch taken. Counts 1–10 shown as `<11` in anything shared.
