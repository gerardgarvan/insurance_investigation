### SECTION 0 — Setup
Load packages: here, glue, dplyr, lubridate, openxlsx2.

### SECTION 1 — V1_SOURCE (Lead L1, map IDs: S4-SRC-02)
Header block:
```r
v1_header <- c(
  "Check ID" = "V1_SOURCE",
  "Lead"     = "L1",
  "Map IDs"  = "S4-SRC-02",
  "Purpose"  = "SOURCE values by CDM table (whole extract and HL cohort); LNK counts per table; patients with >1 SOURCE",
  "Run date" = as.character(run_date)
)
```

Queries (all read-only SQL via DBI::dbGetQuery(pcornet_con, ...)):
1. For each CDM table that has a SOURCE column (check information_schema or try DEMOGRAPHIC, ENCOUNTER, DIAGNOSIS, PROCEDURES, LAB_RESULT_CM, MED_ADMIN, DISPENSING, VITAL, PRO_CM): SELECT UPPER(TRIM(SOURCE)) AS source_norm, COUNT(*) AS n_rows, COUNT(DISTINCT ID) AS n_patients FROM <table> GROUP BY source_norm ORDER BY n_rows DESC. Use tryCatch — skip tables where SOURCE column does not exist.
2. Restrict to HL cohort patients (get HL IDs via: SELECT DISTINCT ID FROM ENCOUNTER WHERE ID IN (SELECT DISTINCT ID FROM DIAGNOSIS WHERE UPPER(DX) LIKE 'C81%' OR UPPER(DX) LIKE '201%')). Re-run the per-table SOURCE query restricted to this HL ID set.
3. LNK counts: for each table, count rows/patients where source_norm = 'LNK'.
4. Multi-source patients: per table, SELECT ID, COUNT(DISTINCT source_norm) AS n_sources FROM <table> GROUP BY ID HAVING n_sources > 1.

**IMPORTANT:** The CONTEXT.md D-01a says re-derive independently. For V1, that means querying CDM tables directly, not calling R/169's `build_single_source_result()`.

Suppress all counts 1–10. No patient IDs in output frames — the multi-source patient frame gets IDs suppressed (show only aggregate counts by n_sources band).

### SECTION 2 — V2_INSURANCE (Lead L2, map IDs: S4-INS-02, S4-INS-03, S4-INS-04)
Header block: check ID = "V2_INSURANCE", lead = "L2", map IDs = "S4-INS-02, S4-INS-03, S4-INS-04".

**Independent re-derivation of the manual's 6-level hierarchy:**
Read PAYER_TYPE from ENCOUNTER directly (do NOT call any pipeline payer function). Implement the manual's 6-level rule directly in dplyr:
```r
# Manual 6-level hierarchy (S4-INS-03):
# 1. Medicaid: PAYER_TYPE IN ('md', 'medicaid', ...) OR payer_code IN ('93','14') OR SOURCE == 'FLM'
# 2. Medicare: PAYER_TYPE matches medicare codes
# 3. Private (incl. Tricare): PAYER_TYPE matches private/tricare codes
# 4. Other
# 5. Uninsured / Self-pay
# 6. Missing (all NA or blank)
```
Read the exact Medicaid code list (93, 14) and FLM source rule from R/00_config.R constants — do not hard-code values that differ from config. Same-day collapse per patient: when a patient has multiple PAYER_TYPE values on the same ADMIT_DATE, apply hierarchy (highest priority wins).

Compare with the pipeline's resolved payer: load the most recent `output/tiered_payer_*.rds` or equivalent (check what R/60 writes — pin via env var R191_PAYER_RDS; stop if absent). Join on patient × date. Compute:
- Agreement rate (n patient-days matching / total)
- Full cross-tab (manual_tier × pipeline_category)
- Discordant cells by category

Patient-day rows that are discordant (different tier assignment): save IDs + dates to `output/internal/am_v2_discordant_patient_days_<date>.rds`. The workbook sheet V2_INSURANCE shows only the cross-tab and agreement rate — no IDs.

### SECTION 3 — V3_DXDATE (Lead L3, map IDs: S4-DXDT-02, S4-DXDT-03, S4-CMNT-02)
Header: check ID = "V3_DXDATE", lead = "L3", map IDs = "S4-DXDT-02, S4-DXDT-03, S4-CMNT-02 (c1)".

**Independent re-derivation of the manual's two-step anchor rule:**
Do NOT call `get_hl_any_dx_ids()`. Instead:
Step 1 — TR default: query TUMOR_REGISTRY_ALL (the TEMP VIEW created by `open_pcornet_con()`) for DIAGNOSISDATE (or equivalent TR date column — check probe; use the column name from `191-CONTEXT.md` or fall back to schema probe). For each ID, take the earliest non-null TR date as the manual's anchor.
Step 2 — HL fallback: for IDs with no TR date, query DIAGNOSIS for DX LIKE 'C81%' (ICD-10 HL codes). Take the earliest ADMIT_DATE per ID. Use UPPER(TRIM(DX)) for matching.

Anchor-date source breakdown:
- n patients with TR date as anchor
- n patients using HL-code fallback
- n patients with no anchor (neither source)

Compare with pipeline anchor dates: load the most recent pipeline cohort RDS (check what R/14 or R/47 writes; pin via env var R191_COHORT_RDS; stop if absent). Join on patient ID. Compute day differences (pipeline_anchor - manual_anchor). Distribution bands: 0 days (exact match), 1–7, 8–30, 31–365, >365, opposite sign.

Suppress counts 1–10.

### SECTION 4 — V4_DXSCOPE (Lead L4, map IDs: S4-DX-01, S4-DX-02, S4-DX-03)
Header: check ID = "V4_DXSCOPE", lead = "L4", map IDs = "S4-DX-01, S4-DX-02, S4-DX-03".

Query purpose: determine whether the ≥2 encounters ≥7 days apart rule (S4-DX-03) is applied to non-HL cancer types in the pipeline.

From DIAGNOSIS: for each patient × cancer-type (using classify_codes() groupings, or if that is too complex, broad ICD-10 prefix categories C00–C96 excluding C81), count:
- n (patient, cancer_type) pairs with ≥2 distinct ADMIT_DATEs that are ≥7 days apart
- n (patient, cancer_type) pairs with <2 dates or dates <7 days apart (would fail the rule)

Then check pipeline output: load the pipeline's cancer-site confirmation artifact (R/44 or R/45 output — check SCRIPT_INDEX for what those write; pin via env var R191_CANCER_RDS; stop if absent). Count how many non-HL cancer-type assignments in the pipeline pass/fail the ≥2/≥7 rule when re-checked against raw DIAGNOSIS.

Report: counts by cancer type category (HL, NHL, other B-cell, other) — do/do not meet rule. Suppress 1–10.

### SECTION 5 — V5_ZIPCOVER (Lead L5 data side, map IDs: S4-ADI-01, S4-ADI-02, S4-ADI-03, S4-ADI-04, S4-ADI-05)
Header: check ID = "V5_ZIPCOVER", lead = "L5", map IDs = "S4-ADI-01, S4-ADI-02, S4-ADI-03, S4-ADI-04, S4-ADI-05".

- Encounters with ZIP9 (9-digit non-null, non-sentinel)
- Encounters with ZIP5 only (5-digit present, ZIP9 absent)
- Encounters with no usable ZIP (both absent or sentinel)
Report as n_encounters and n_patients in each tier.

Load the pipeline's SES index output (R/116 encounter_ses_index RDS — pin via env var R191_SES_RDS; stop if absent). Count:
- Patients receiving ADI (adi_natrank not NA)
- Patients receiving SDI (sdi_score not NA)
- Patients receiving imputed values (match_type == 'approximate' or similar — check the RDS columns from the SCRIPT_INDEX description of R/116)

Suppress 1–10.

### SECTION 6 — V6_DEATH (Lead L6, map IDs: S4-DTH-02, S4-DTH-03, S4-DTH-04)
Header: check ID = "V6_DEATH", lead = "L6", map IDs = "S4-DTH-02, S4-DTH-03, S4-DTH-04".

Query DEATH table joined to the HL cohort patient list. For each deceased cohort patient, find their last treatment encounter date (from pipeline treatment episodes RDS — pin via env var R191_EPISODES_RDS; stop if absent). Compute gap = death_date − last_treatment_date. Band patients by gap:
- 1–14 days (14-day rule would remove)
- 15–30 days (30-day rule would also remove; 14-day rule would not)
- 31–90 days
- >90 days
- death_date AFTER last treatment (gap > 0 — death after treatment, expected pattern)
- gap = 0 or death_date = last_treatment_date (edge case)

Report: n patients in each band (suppressed). How many the 14-day rule removes vs a 30-day rule would remove.

DEATH_CAUSE check: COUNT(DISTINCT ID) of cohort patients excluded from the cohort due to DEATH_CAUSE criteria. Expected = 0 (manual says do not use cause of death). Pull from pipeline exclusion logic if accessible, otherwise note "DEATH_CAUSE usage not detectable from available artifacts".
