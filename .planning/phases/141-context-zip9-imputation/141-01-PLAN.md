### approximate_zip9() — the function being wired (utils_address.R ~line 343)

```r
approximate_zip9 <- function(result_tbl)
```

**Input contract** (`result_tbl` = tibble returned by `get_zip9_at_date()`):
- Required columns: `ID`, `query_date`, `ZIP9`, `ZIP5`, `match_type`
- Must NOT already carry provenance columns (`zip9_source`, `zip5_modal_freq`,
  `zip5_n_candidates`, `zip5_modal_share`) — the idempotency guard returns input
  unchanged if any of those are present.

**Output contract** — same row count as input, same 5 columns PLUS 4 provenance columns:
- `zip9_source` (character): one of `"zip9_observed"`, `"zip5_modal"`,
  `"zip5_no_zip9"`, `"no_zip5"`, `"none"`, `"reference_unavailable"`, `"invalid_input"`
- `zip5_modal_freq` (integer): distinct-patient modal frequency for the matched ZIP5
- `zip5_n_candidates` (integer): number of ZIP9 candidates for that ZIP5
- `zip5_modal_share` (double): modal_freq / sum(freq) for that ZIP5

**Probe-first gate (D-08):** If `LDS_ADDRESS_HISTORY_Mailhot_V1.csv` is absent from
`CONFIG$data_dir`, returns `result_tbl` unchanged (all rows get `zip9_source =
"reference_unavailable"`). R/115 does not need to guard this call — `approximate_zip9()`
handles it internally.

**Idempotency guard:** If provenance columns already exist, returns input unchanged with
a console message. Do not call `approximate_zip9()` twice on the same tibble.
