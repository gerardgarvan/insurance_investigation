### `autoimmune_dx_code_system` column (D-04)

- **D-04:** Character column appended as the third and last autoimmune column (after `first_autoimmune_dx_date`). Column count goes from 22 to 23.

  **Values** (based on all qualifying records with a valid date — same set that drives `has_autoimmune_dx`):

  | Value | Meaning |
  |-------|---------|
  | `"ICD-9"` | Every qualifying, validly-dated record is ICD-9 |
  | `"ICD-10"` | Every qualifying, validly-dated record is ICD-10 |
  | `"Both"` | At least one ICD-9 and at least one ICD-10 qualifying record |
  | `NA` | `has_autoimmune_dx = FALSE` |

  Invariant: `is.na(autoimmune_dx_code_system) ↔ has_autoimmune_dx == FALSE`. Asserted in code and R/88.

  The raw `DX_TYPE` values ("09"/"10") are used only for matching; the readable labels above go into the output.

- **D-05:** For patients with `qc_qualifying_no_valid_date = TRUE` (qualifying code but no valid date → `has_autoimmune_dx = FALSE`): `autoimmune_dx_code_system = NA` in the CSV. The code-system breakdown for these patients (ICD-9 / ICD-10 / Both) is printed to the QC console output only, not written to any Gantt output.

### `summarise_autoimmune_dx()` extension (D-06)

- **D-06:** Extend `summarise_autoimmune_dx()` in `R/utils/utils_doi.R` to also compute and return `autoimmune_dx_code_system`. The derivation happens on the same qualifying, validly-dated subset already used for `first_autoimmune_dx_date`. Callers (`R/52`, `R/142`) receive the new column automatically; they select it alongside the two existing columns before joining into the Gantt output.

### Output inventory and run order (D-07)

- **D-07:** Same output inventory as Phase 192.1: `gantt_episodes.csv` (90-day), `gantt_episodes_180.csv`, and R/170 outputs. Run order for HiPerGator:
  1. R/52 → regenerate `gantt_episodes.csv` (23 columns)
  2. R/142 → regenerate `gantt_episodes_180.csv` (23 columns)
  3. R/170 → REPIN branch picks up `autoimmune_dx_code_system` automatically; JOIN branch must also patch in the new column from the new build

  R/170 JOIN branch: extend the three-column `distinct()` + join to include `autoimmune_dx_code_system`; assert all three autoimmune columns present in every R/170 output.

### Regression check (D-08)

- **D-08:** Re-run the D-08 comparison from 192.1 (row count, original column order/values, key multiplicities) on the regenerated CSVs, using the 192.1 baselines (`*_PRE1921.csv`) that already exist in `output/internal/`. `autoimmune_dx_code_system` is a new column — exclude it from the original-column comparison. Save new baselines (`*_PRE1922.csv`) in `output/internal/` after the comparison passes.

### R/88 updates (D-09)

- **D-09:** Two-section approach:
  - **In SECTION 15ba:** Remove the two outdated checks (`AUTOIMMUNE-FLAG-02 [g]` icd9 slot is empty, and the column-count = 22 check in AUTOIMMUNE-FLAG-03); replace each with a comment pointing to `15bb`. Leave all other 15ba checks intact.
  - **Add SECTION 15bb (Phase 192.2 checks):**
    - (a) `AUTOIMMUNE_DX_CODES$icd9` has the expected keys (spot-check a subset: 7140, 4464, 6961)
    - (b) `is_autoimmune_code("7140", "09")` returns TRUE; `is_autoimmune_code("7140", "10")` returns FALSE
    - (c) Column count = 23 in both gantt CSVs
    - (d) `autoimmune_dx_code_system` is the last column in both CSVs
    - (e) `autoimmune_dx_code_system` parses as character; values in `{"ICD-9", "ICD-10", "Both", NA}`
    - (f) NA ↔ FALSE invariant: `all(is.na(code_system) == !has_autoimmune_dx)`
    - (g) Every patient with `autoimmune_dx_code_system %in% c("ICD-9", "Both")` has `first_autoimmune_dx_date <= as.Date("2015-10-01")` **or** appears in the QC-qualifying-no-valid-date printout (ICD-10 became mandatory 2015-10-01; ICD-9-only patients must pre-date the transition)
    - (h) All three R/170 outputs have all three autoimmune columns
