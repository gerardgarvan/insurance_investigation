# 161-01 — Fix ingest typing: DEATH_DATE_IMPUTE as VARCHAR; rebuild DuckDB

**Wave:** 1
**Depends on:** none
**Requires team sign-off:** no

## Goal

Correct the R/03 ingest script so `DEATH_DATE_IMPUTE` is stored as VARCHAR (not DATE) in DuckDB, preserving the B/D/M/N flag values that are currently all NULL, then rebuild the DuckDB database from the RDS cache.

## Steps

1. Open `R/03_duckdb_ingest.R`. Locate the block at lines 159–169 that auto-detects Date columns via `inherits(df[[col]], "Date")` and coerces pre-1900 sentinels to NA.

2. Immediately before that Date-coercion block, add a guard that converts `DEATH_DATE_IMPUTE` to character for the DEATH table before the auto-detection runs:

   ```r
   # 161-01: DEATH_DATE_IMPUTE is a B/D/M/N flag, not a date.
   # R/01 loads it as col_character(), but confirm and force here to prevent
   # any future col_type drift from silently nulling the flag.
   if (tbl_name == "DEATH" && "DEATH_DATE_IMPUTE" %in% names(df)) {
     df[["DEATH_DATE_IMPUTE"]] <- as.character(df[["DEATH_DATE_IMPUTE"]])
     message("  [161-01] DEATH_DATE_IMPUTE coerced to character before DuckDB write")
   }
   ```

   Place this block BEFORE the line `date_cols_in_df <- names(df)[sapply(df, inherits, "Date")]` so the column is never picked up by the Date auto-detection logic.

3. Confirm in `R/01_load_pcornet.R` that the DEATH col_types spec already has `DEATH_DATE_IMPUTE = col_character()` (it does, at lines 217–218). No change needed there; document the consistency in a comment in R/03.

4. Run a full DuckDB rebuild on HiPerGator:

   ```bash
   module load R/4.4.2
   Rscript R/03_duckdb_ingest.R
   ```

   The atomic write pattern in R/03 (build at `.tmp`, rename on success) protects the existing database if the rebuild fails.

5. After rebuild, open a quick R session and verify:

   ```r
   source("R/00_config.R")
   con <- DBI::dbConnect(duckdb::duckdb(), CONFIG$cache$duckdb_path, read_only = TRUE)
   DBI::dbGetQuery(con, "
     SELECT DEATH_DATE_IMPUTE, COUNT(*) AS n
     FROM DEATH
     GROUP BY DEATH_DATE_IMPUTE
     ORDER BY n DESC
   ")
   DBI::dbDisconnect(con)
   ```

   Expected: rows with values `B`, `D`, `M`, `N`, or similar PCORnet codes; no rows where `DEATH_DATE_IMPUTE` is NULL except legitimately missing records.

6. Verify the DuckDB column type with:

   ```r
   DBI::dbGetQuery(con, "DESCRIBE DEATH")
   # DEATH_DATE_IMPUTE row must show VARCHAR, not DATE
   ```

## Acceptance criteria

- `DEATH_DATE_IMPUTE` column type is VARCHAR in `pcornet.duckdb` (confirmed via `DESCRIBE DEATH`).
- Non-null B/D/M/N values are present in the column; the all-NULL state from the defective ingest is gone.
- The ingest log CSV at `output/logs/duckdb_ingest_<EXTRACT_DATE>.csv` records a successful DEATH table row with the expected row count.
- No other date columns regressed: all other columns whose names contain `DATE` remain typed DATE (verify via `DESCRIBE DIAGNOSIS`, `DESCRIBE ENCOUNTER`, `DESCRIBE DEATH` — only `DEATH_DATE_IMPUTE` should be VARCHAR among DATE-named columns).
- R/03 script exits without warnings about DEATH_DATE_IMPUTE.
