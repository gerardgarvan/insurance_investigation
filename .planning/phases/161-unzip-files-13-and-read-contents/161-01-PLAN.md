# 161-01 — Snapshot R/147 outputs; locate and fix DEATH_DATE_IMPUTE loss; rebuild DuckDB

**Wave:** 1
**Depends on:** none
**Requires team sign-off:** no

## Goal

Preserve the pre-161 R/147 outputs for the 161-08 comparison, find the exact step
where `DEATH_DATE_IMPUTE` values (B/D/M/N) become NULL, fix it at that step, and
rebuild the RDS cache and DuckDB so the column is VARCHAR and populated.

The diagnostic found the column typed DATE with **0** non-null values. Coercing a
Date column back to character in R/03 would only produce `NA` strings, so the fix
must be made where the values are first lost.

## Steps

1. **Snapshot R/147 outputs (do this first — 161-05 overwrites them).**

   ```bash
   cd /blue/erin.mobley-hl.bcu/insurance_investigation
   mkdir -p output/before_161
   ls -l output/ | grep -i -E "147|modality|E_patient"      # confirm the file set
   cp -p output/*147* output/before_161/ 2>/dev/null
   cp -p output/*E_patient_modality_dates* output/before_161/ 2>/dev/null
   ls -l output/before_161/                                  # must not be empty
   ```

   If R/147 writes to a subfolder, copy that folder instead. Record the file list in
   the 161-01 summary.

2. **Check the raw extract.** Locate the raw DEATH file path in `R/00_config.R` and
   inspect the column directly:

   ```r
   source("R/00_config.R")
   raw <- readr::read_csv(<raw DEATH path>, col_types = readr::cols(.default = "c"))
   table(raw$DEATH_DATE_IMPUTE, useNA = "ifany")
   ```

   If the raw values are all blank, the flags are absent at the source: document
   this, skip to step 6, and note in 161-CONTEXT.md that imputed death dates cannot
   be identified in this extract.

3. **Check the R/01 load and the RDS cache.**

   ```r
   d <- readRDS(<DEATH RDS cache path from CONFIG>)
   class(d$DEATH_DATE_IMPUTE)
   table(d$DEATH_DATE_IMPUTE, useNA = "ifany")
   ```

   ```bash
   grep -n -E 'contains\("DATE"\)|ends_with\("DATE"\)|matches\(".*DATE|_DATE' R/01_load_pcornet.R
   grep -n -E 'DATE' R/03_duckdb_ingest.R | head -40
   ```

   Identify which step converts the column (e.g. a name-pattern date parser applied
   after `read_csv`, or a cache written before `col_character()` was added).

4. **Fix at the point of loss.**
   - If a name-pattern date parser is the cause, restrict it to columns whose names
     **end** in `_DATE` (`ends_with("_DATE")`), which excludes `DEATH_DATE_IMPUTE`.
   - If the cache is stale, delete the DEATH cache entry so R/01 rebuilds it.

5. **Add a defensive guard in R/03** before the Date auto-detection block
   (`date_cols_in_df <- names(df)[sapply(df, inherits, "Date")]`). The guard stops
   instead of coercing, so a future regression fails loudly:

   ```r
   # 161-01: DEATH_DATE_IMPUTE is a B/D/M/N flag, not a date. If it arrives as Date,
   # the values were already lost upstream (R/01 or cache); coercing would hide that.
   if (tbl_name == "DEATH" && "DEATH_DATE_IMPUTE" %in% names(df)) {
     if (inherits(df[["DEATH_DATE_IMPUTE"]], c("Date", "POSIXt"))) {
       stop("[161-01] DEATH_DATE_IMPUTE arrived as Date; flag values were lost upstream. ",
            "Fix R/01 / rebuild the DEATH cache before ingesting.")
     }
     df[["DEATH_DATE_IMPUTE"]] <- as.character(df[["DEATH_DATE_IMPUTE"]])
   }
   ```

6. **Rebuild** the cache (if step 4 required it) and DuckDB:

   ```bash
   module load R/4.4.2
   Rscript R/01_load_pcornet.R        # only if the DEATH cache was invalidated
   Rscript R/03_duckdb_ingest.R
   ```

   R/03 builds at `TMP_PATH` and renames on success, so the existing database at
   `/blue/erin.mobley-hl.bcu/clean/duckdb/pcornet.duckdb` is protected if it fails.

7. **Verify.**

   ```r
   source("R/00_config.R")
   con <- DBI::dbConnect(duckdb::duckdb(), CONFIG$cache$duckdb_path, read_only = TRUE)
   DBI::dbGetQuery(con, "SELECT DEATH_DATE_IMPUTE, COUNT(*) AS n FROM DEATH GROUP BY 1 ORDER BY n DESC")
   DBI::dbGetQuery(con, "
     SELECT table_name, column_name, data_type
       FROM information_schema.columns
      WHERE data_type = 'DATE' AND NOT regexp_matches(upper(column_name), '_DATE$')")
   DBI::dbDisconnect(con, shutdown = TRUE)
   ```

   The second query must return 0 rows (no DATE-typed column whose name does not end
   in `_DATE`).

## Acceptance criteria

- `output/before_161/` contains the pre-161 R/147 outputs (non-empty, listed in the summary).
- The step where the flag values were lost is identified and documented.
- `DEATH_DATE_IMPUTE` is VARCHAR in `pcornet.duckdb`, and its value distribution
  matches the raw extract (or the raw extract is documented as having no flags).
- No DATE-typed column exists whose name does not end in `_DATE`.
- All columns ending in `_DATE` in DIAGNOSIS, ENCOUNTER, DEATH remain DATE.
- R/03 contains the stop-on-Date guard; the ingest log records a successful DEATH row count.
