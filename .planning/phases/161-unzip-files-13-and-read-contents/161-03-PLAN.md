# 161-03 — Shared resolve_death_date() utility; sensitivity table at N=0/30/60/90/365

**Wave:** 3
**Depends on:** 161-02
**Requires team sign-off:** yes (D1 grace period = 30 days and D2 flag-not-exclude must be confirmed before this executes)

## Goal

Implement `resolve_death_date()` in a new shared utility file `R/utils/utils_death.R`, applying the D1–D3 rules, and write a sensitivity table showing patient counts flagged as implausible at each candidate grace period so the N=30 choice is documented rather than assumed.

## Steps

1. Create `R/utils/utils_death.R`. At the top, add a roxygen header describing inputs and outputs. The function signature is:

   ```r
   resolve_death_date <- function(death_tbl, activity_tbl, grace_days = 30) {
     # death_tbl:    data frame with columns ID, DEATH_DATE (Date), DEATH_SOURCE (character, may be NA)
     # activity_tbl: data frame with columns ID, last_activity_date (Date) — latest CDM event <= cutoff
     # grace_days:   integer, days of allowed post-death activity before flagging as implausible (D1)
     #
     # Returns one row per ID with columns:
     #   death_date_raw         — earliest raw DEATH_DATE from DEATH (before plausibility check)
     #   death_date_resolved    — date after applying D2/D3 rules; NA if no plausible date
     #   death_flag             — character: "plausible" | "implausible_post_activity" |
     #                            "conflicting_resolved" | "conflicting_unresolved" | "no_death_record"
     #   post_death_activity_days — integer, days of activity beyond death_date_raw (0 if plausible)
   }
   ```

2. Implement the function body in four stages:

   **Stage A — Detect conflicting dates (D3).**
   Group `death_tbl` by ID. Patients with more than one distinct DEATH_DATE are "conflicting."

   **Stage B — Resolve conflicting dates (D3).**
   For conflicting patients, left-join to `activity_tbl`. A death date is "consistent" if:
   `DEATH_DATE >= (last_activity_date - grace_days)`
   Among consistent dates, choose the *earliest* (D3: "earliest consistent is safer"). If `DEATH_SOURCE` is populated among the consistent dates, apply source priority as a tiebreaker: NDI or state death files > SSA > local/tumor-registry records (match on case-insensitive substrings "NDI", "STATE", "SSA", "LOCAL", "TUMOR"). If no consistent date exists, set `death_flag = "conflicting_unresolved"` and apply D2.

   **Stage C — Check plausibility for non-conflicting patients (D1/D2).**
   For patients with a single death date (or after conflict resolution), check:
   `last_activity_date > (death_date_resolved + grace_days)`
   If TRUE: `death_flag = "implausible_post_activity"`, set `death_date_resolved = last_activity_date` (end follow-up at last observed activity per D2).
   If FALSE: `death_flag = "plausible"`.

   **Stage D — Patients with no DEATH record.**
   Anti-join from `activity_tbl` to `death_tbl`. Set `death_date_resolved = NA`, `death_flag = "no_death_record"`.

3. After the main function, add a helper `death_sensitivity_table()`:

   ```r
   death_sensitivity_table <- function(death_tbl, activity_tbl,
                                       grace_values = c(0, 30, 60, 90, 365)) {
     # Runs resolve_death_date() at each grace_days value.
     # Returns a data frame: grace_days | n_implausible | n_conflicting_unresolved | n_plausible
   }
   ```

   This is called by 161-03 itself (see step 5) and may be called by 161-05 for reporting.

4. Add `source("R/utils/utils_death.R")` to `R/00_config.R` alongside the other `source()` calls for utils files, so every downstream script gets the function automatically.

5. Write a standalone driver script `R/161_death_sensitivity.R` that:
   - Sources `R/00_config.R`.
   - Reads the DEATH and ENCOUNTER tables from DuckDB.
   - Constructs `activity_tbl` as the latest event date per patient across ENCOUNTER (using `pmax(ADMIT_DATE, DISCHARGE_DATE, na.rm = TRUE)`), DIAGNOSIS, PROCEDURES (all <= cutoff).
   - Calls `death_sensitivity_table()` with `grace_values = c(0, 30, 60, 90, 365)`.
   - Writes the result to `output/161_death_sensitivity.csv` and prints it to the console.
   - Reports that at N=30, the implausible count matches the 261 from the original diagnostic (or explains any difference due to the 161-01 DEATH_DATE_IMPUTE fix).

6. Run `R/161_death_sensitivity.R` on HiPerGator:

   ```bash
   module load R/4.4.2
   Rscript R/161_death_sensitivity.R
   ```

## Acceptance criteria

- `R/utils/utils_death.R` exists with `resolve_death_date()` and `death_sensitivity_table()` exported (no `::` needed after sourcing via 00_config).
- `resolve_death_date()` returns exactly one row per patient ID present in either `death_tbl` or `activity_tbl`.
- `death_flag` takes only the four allowed values: `plausible`, `implausible_post_activity`, `conflicting_resolved`, `conflicting_unresolved`, plus `no_death_record` for patients without a DEATH row.
- At `grace_days = 30`, `n_implausible` matches the 261 cases from the 161-CONTEXT.md diagnostic (within any small delta attributable to the DEATH_DATE_IMPUTE fix — document if different).
- `output/161_death_sensitivity.csv` exists with rows for N = 0, 30, 60, 90, 365.
- `R/00_config.R` sources `R/utils/utils_death.R` so the function is available to all scripts without per-script sourcing.
- Script exits cleanly; no warnings about missing columns or NA coercions.
