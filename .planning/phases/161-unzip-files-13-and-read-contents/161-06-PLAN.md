# 161-06 — Tests: test-161-death-plausibility.R fixtures + R/88 assertions

**Wave:** 4
**Depends on:** 161-03, 161-04
**Requires team sign-off:** no

## Goal

Create `tests/testthat/test-161-death-plausibility.R` with fixture-driven unit tests covering all `resolve_death_date()` scenarios, and add two new assertions to `R/88_smoke_test_comprehensive.R` to permanently guard against the DEATH_DATE_IMPUTE typing defect and the follow_end >= hl_anchor_date invariant.

## Steps

1. Create `tests/testthat/test-161-death-plausibility.R`. At the top, source the config and the new utility:

   ```r
   library(testthat)
   source(here::here("R/00_config.R"))
   # resolve_death_date() is available after sourcing 00_config.R (per 161-03 step 4)
   ```

2. Build synthetic fixtures as local tibbles (no DuckDB connection needed). Create a helper at the top of the file:

   ```r
   make_death <- function(id, date, source = NA_character_) {
     tibble::tibble(ID = id, DEATH_DATE = as.Date(date), DEATH_SOURCE = source)
   }
   make_activity <- function(id, last_date) {
     tibble::tibble(ID = id, last_activity_date = as.Date(last_date))
   }
   ```

3. Write the following test cases (one `test_that()` block per scenario):

   **Scenario 1 — Death before diagnosis, single death date.**
   Patient A has DEATH_DATE = "2010-01-01", last_activity_date = "2015-06-01" (5 years later).
   At grace_days = 30: flag must be `implausible_post_activity`.
   `death_date_resolved` must equal last_activity_date ("2015-06-01").

   **Scenario 2 — Death before diagnosis, conflicting death dates, none consistent.**
   Patient B has two DEATH rows: "2010-01-01" and "2011-03-15". last_activity_date = "2015-06-01".
   Neither date is >= 2015-06-01 - 30 days. Flag must be `conflicting_unresolved`.
   `death_date_resolved` must equal last_activity_date.

   **Scenario 3 — Conflicting death dates, one consistent.**
   Patient C has two DEATH rows: "2010-01-01" and "2020-08-10". last_activity_date = "2020-07-15".
   "2020-08-10" >= "2020-07-15" - 30 = "2020-06-15". Consistent.
   "2010-01-01" is not consistent.
   Flag must be `conflicting_resolved`. `death_date_resolved` must be "2020-08-10" (earliest consistent).

   **Scenario 4 — Post-death activity within grace period (plausible).**
   Patient D has DEATH_DATE = "2021-03-01", last_activity_date = "2021-03-20" (19 days after death).
   At grace_days = 30: 19 <= 30, so flag must be `plausible`.
   `death_date_resolved` must equal DEATH_DATE ("2021-03-01").

   **Scenario 5 — Post-death activity beyond grace period (implausible).**
   Patient E has DEATH_DATE = "2021-03-01", last_activity_date = "2021-05-15" (75 days after death).
   At grace_days = 30: 75 > 30, so flag must be `implausible_post_activity`.
   `death_date_resolved` must equal last_activity_date ("2021-05-15").

   **Scenario 6 — Inpatient anchor with later discharge; follow-up extension.**
   This scenario tests `compute_followup()`, not `resolve_death_date()`. Patient F:
   `hl_anchor_date = "2020-06-10"`, `ADMIT_DATE = "2020-06-10"`, `DISCHARGE_DATE = "2020-06-18"`, no death.
   `obs_end` (from updated `compute_followup()`) must be "2020-06-18", not "2020-06-10".
   `fu_status` must be "positive" (8 days > 0).

   **Scenario 7 — Zero follow-up patient after fix.**
   Patient G: `hl_anchor_date = "2020-06-10"`, `obs_end = "2020-06-10"` (admit = discharge = anchor date), no death, cutoff = "2025-12-31".
   `follow_end` = "2020-06-10". `fu_status` must be "zero". Must NOT be "negative".

   **Scenario 8 — No death record.**
   Patient H is in `activity_tbl` but not in `death_tbl`.
   Flag must be `no_death_record`. `death_date_resolved` must be NA.

4. Add two new assertion blocks to `R/88_smoke_test_comprehensive.R`:

   **Assertion A — DEATH_DATE_IMPUTE is VARCHAR and populated:**

   ```r
   # 161-01 guard: DEATH_DATE_IMPUTE must be VARCHAR with non-NULL values
   death_impute_check <- DBI::dbGetQuery(con, "
     SELECT
       COUNT(*)                                              AS total_rows,
       COUNT(DEATH_DATE_IMPUTE)                             AS non_null_rows,
       typeof(DEATH_DATE_IMPUTE)                            AS col_type
     FROM DEATH
     LIMIT 1
   ")
   # Actually need per-column type from DESCRIBE
   death_schema <- DBI::dbGetQuery(con, "DESCRIBE DEATH")
   impute_type <- death_schema |>
     dplyr::filter(column_name == "DEATH_DATE_IMPUTE") |>
     dplyr::pull(column_type)
   stopifnot(
     "[R/88 161-01] DEATH_DATE_IMPUTE must be VARCHAR" =
       grepl("VARCHAR|CHARACTER|TEXT", impute_type, ignore.case = TRUE)
   )
   # Confirm non-null values exist (flag column should not be all NULL)
   n_non_null <- DBI::dbGetQuery(con,
     "SELECT COUNT(*) AS n FROM DEATH WHERE DEATH_DATE_IMPUTE IS NOT NULL")$n
   stopifnot(
     "[R/88 161-01] DEATH_DATE_IMPUTE must have non-NULL values" = n_non_null > 0
   )
   message(glue("[R/88] DEATH_DATE_IMPUTE: VARCHAR, {n_non_null} non-NULL rows. PASS"))
   ```

   **Assertion B — follow_end >= hl_anchor_date for all retained patients:**
   This assertion runs after `compute_followup()` is called within R/88 or via a shared helper. Add:

   ```r
   # 161-04 guard: no retained patient may have follow_end < hl_anchor_date
   n_negative_fu <- followup_smoke |>
     dplyr::filter(!is.na(follow_end), follow_end < hl_anchor_date) |>
     nrow()
   stopifnot(
     "[R/88 161-04] No patient should have follow_end < hl_anchor_date" =
       n_negative_fu == 0
   )
   message(glue("[R/88] follow_end >= hl_anchor_date for all retained patients. PASS"))
   ```

   (`followup_smoke` should be constructed in R/88 using the same `compute_followup()` call pattern as R/147, using `death_resolved` from `resolve_death_date()`.)

5. Run the tests locally (or on HiPerGator if DuckDB not available locally):

   ```bash
   module load R/4.4.2
   Rscript -e 'testthat::test_file("tests/testthat/test-161-death-plausibility.R")'
   ```

6. Run R/88 to confirm both new assertions pass:

   ```bash
   Rscript R/88_smoke_test_comprehensive.R
   ```
