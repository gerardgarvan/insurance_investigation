## Goal

Update `R/147_surveillance_modality_frequency.R` to use `get_last_activity()`,
`resolve_death_date()` and the new `compute_followup()`; report counts by
`death_flag` and `fu_status`; write a sensitivity analysis excluding patients with no
credible death date; and classify anchor-day events as "pre" (D5).

Pre-161 outputs were saved to `output/before_161/` in 161-01, so this task may
overwrite the current R/147 outputs.

## Steps

1. List every `compute_followup()` call and every direct DEATH read in R/147.

2. Replace the follow-up block (≈ line 251) with:

   ```r
   # 161-05: shared activity and death definitions (D1-D4)
   activity       <- get_last_activity(con, cohort, CUTOFF_DATE)
   death_rows     <- <DEATH rows for cohort: ID, DEATH_DATE, DEATH_SOURCE>
   death_resolved <- resolve_death_date(death_rows, activity, grace_days = 30L)  # D1
   followup       <- compute_followup(cohort, activity, death_resolved, CUTOFF_DATE)
   ```

   Remove any other derivation of last encounter or death date in R/147.

3. Flag summary (aggregate only):

   ```r
   flag_summary <- dplyr::count(followup, death_flag, fu_status, fu_reason)
   message("[161-05] death_flag x fu_status x fu_reason:")
   print(flag_summary, n = Inf)
   readr::write_csv(flag_summary, "output/161_flag_summary.csv")
   ```

4. Main analysis (D2): retain all patients. Patients with `death_flag` in
   {`implausible_post_activity`, `conflicting_unresolved`} have
   `death_date_resolved = NA` and follow-up ending at `obs_end`. Confirm no filter
   downstream drops them and none is counted as deceased.

5. Sensitivity analysis (D2): after the main tables are written,

   ```r
   cohort_sensitivity <- dplyr::filter(
     followup, !death_flag %in% c("implausible_post_activity", "conflicting_unresolved"))
   ```

   Re-run the per-modality calculation on `cohort_sensitivity`; write
   `output/147_surveillance_sensitivity_excl_no_credible_death.csv`; print the
   difference in N, person-years, and modality rates versus the main analysis.

6. Anchor-day rule (D5). In `classify_event_window()` (`utils_surveillance.R`
   ≈ line 453) or its R/147 equivalent:

   ```r
   event_date <= hl_anchor_date ~ "pre",            # D5: anchor-day events are pre
   event_date >  follow_end     ~ "after_followup",
   TRUE                         ~ "post"
   ```

   If "pre" currently uses `<`, change it to `<=` with a D5 comment, and record how
   many events moved from "post" to "pre".

7. Reporting: show `zero` and `negative` as separate rows in summaries (with
   `fu_reason`), replacing `zero_or_negative`.

8. Run:

   ```bash
   module load R/4.4.2
   Rscript R/147_surveillance_modality_frequency.R
   ```
