# 161-05 — R/147 reporting: death_flag counts, sensitivity exclusion analysis, anchor-day classification

**Wave:** 4
**Depends on:** 161-03, 161-04
**Requires team sign-off:** no

## Goal

Update `R/147_surveillance_modality_frequency.R` to use the revised `compute_followup()` (which now accepts `death_resolved`), report patient counts by `death_flag` and `fu_status` in the output log, produce a sensitivity analysis excluding implausible-death-date patients alongside the main analysis, and enforce D5 anchor-day classification (events on `hl_anchor_date` are "pre", not "post").

## Steps

1. Open `R/147_surveillance_modality_frequency.R`. Identify every call to `compute_followup()` and every place the DEATH table is read directly.

2. Before the call to `compute_followup()`, add a call to `resolve_death_date()`:

   ```r
   # 161-05: Resolve death dates per D1–D3 before computing follow-up
   death_resolved <- resolve_death_date(
     death_tbl    = death_raw,       # raw DEATH table from DuckDB
     activity_tbl = activity_for_death_check,  # latest CDM event per patient <= cutoff
     grace_days   = 30               # D1: locked at N = 30
   )
   ```

   `activity_for_death_check` is the same `obs_end` derivation from `compute_followup()` — extract it to a named object so both functions can share it. If `compute_followup()` was refactored in 161-04 to accept an `activity_tbl` separately, reuse that object.

3. Pass `death_resolved` to `compute_followup()`:

   ```r
   followup <- compute_followup(
     denominator    = cohort,
     last_enc       = encounter_for_fu,
     cutoff         = CUTOFF_DATE,
     death_resolved = death_resolved
   )
   ```

4. After computing `followup`, add a death-flag summary log block:

   ```r
   # --- 161-05: death_flag and fu_status summary ---
   flag_summary <- followup |>
     dplyr::count(death_flag, fu_status) |>
     dplyr::arrange(death_flag, fu_status)
   message("[161-05] death_flag x fu_status counts:")
   print(flag_summary, n = Inf)
   ```

   Write `flag_summary` to `output/161_flag_summary.csv`.

5. Apply D2 consistently for the main analysis: patients with `death_flag == "implausible_post_activity"` are retained in the main cohort with `follow_end = last_activity_date` (this is already handled by `resolve_death_date()` returning `death_date_resolved = last_activity_date` for those patients — confirm no additional filtering removes them).

6. Produce a sensitivity analysis excluding flagged patients. After the main output tables are written, add:

   ```r
   # --- 161-05: Sensitivity analysis — exclude implausible death-date patients ---
   cohort_sensitivity <- followup |>
     dplyr::filter(
       death_flag %in% c("plausible", "no_death_record", "conflicting_resolved")
     )
   ```

   Re-run the per-modality rate calculation using `cohort_sensitivity`. Write results to `output/147_surveillance_sensitivity_excl_implausible.csv`. Print the difference in person-years and modality rates versus the main analysis.

7. Enforce D5: confirm the event-window classification in R/147. Find the `case_when` or `if_else` that assigns events to "pre" / "post" / "during" windows. Ensure the condition for "pre" is:

   ```r
   event_date <= hl_anchor_date ~ "pre"
   ```

   (Less-than-or-equal, so anchor-day events are "pre". "Post" must be strictly `event_date > hl_anchor_date`.) If the existing code uses `<` for "pre" (which would leave anchor-day events unclassified or in "post"), change it to `<=` and add a comment citing D5.

8. In the output log / console summary, report zero-follow-up patients (`fu_status == "zero"`) separately from negative (`fu_status == "negative"`) per D5. If R/147 currently lumps these, split the reporting.

9. Run `R/147_surveillance_modality_frequency.R` on HiPerGator and confirm it completes without error:

   ```bash
   module load R/4.4.2
   Rscript R/147_surveillance_modality_frequency.R
   ```

- `R/147_surveillance_modality_frequency.R` calls `resolve_death_date()` and passes `death_resolved` to `compute_followup()` — no direct use of raw death dates in person-time calculation.
- `output/161_flag_summary.csv` exists with counts by `death_flag` and `fu_status`.
- Main analysis retains implausible-death-date patients (count matches `n_implausible` from 161-03 sensitivity table at N=30).
- `output/147_surveillance_sensitivity_excl_implausible.csv` exists and shows modality rates and person-years when those patients are excluded.
- Events on `hl_anchor_date` are classified as "pre" in all window-assignment logic.
- Zero-follow-up patients (`fu_status == "zero"`) appear as their own row in output summaries, not merged with negative-follow-up.
- Script completes without warnings about deprecated `death` argument (it passes `death_resolved` directly).
