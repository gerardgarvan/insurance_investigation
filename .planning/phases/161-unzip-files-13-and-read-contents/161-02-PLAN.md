# 161-02 — Re-run diagnostic on rebuilt DuckDB; record n_conflicting / n_death_max_reconciles

**Wave:** 2
**Depends on:** 161-01
**Requires team sign-off:** no

## Goal

Re-run `R/161_diag_anchor_followup.R` against the rebuilt DuckDB (which now has `DEATH_DATE_IMPUTE` as VARCHAR) to fill in the two counts that were marked "pending" in 161-CONTEXT.md: how many patients have conflicting death dates across DEATH rows, and how many of those conflicts D3's "earliest-consistent" rule resolves.

## Steps

1. On HiPerGator, run the diagnostic script with wide output so no columns are truncated:

   ```bash
   module load R/4.4.2
   Rscript -e '
     options(width = 200)
     source("R/161_diag_anchor_followup.R")
   '
   ```

2. From the output, capture:
   - **n_conflicting** — patients with more than one distinct death date across DEATH rows.
   - **n_death_impute_not_null** — patients where `DEATH_DATE_IMPUTE` is now non-NULL (was all-NULL before 161-01 fix). This confirms the ingest fix propagated correctly.
   - **n_category_2a** — patients with imputed death dates (DEATH_DATE_IMPUTE in B/D/M) now that the flag is readable.
   - **n_death_max_reconciles** — of the conflicting patients, how many have at least one death date that is consistent with clinical activity (i.e., death_date >= last_activity_date - 30 days) and therefore resolvable by the D3 "earliest-consistent" rule.

3. If the diagnostic script does not yet compute `n_conflicting` or `n_death_max_reconciles`, add the following section to `R/161_diag_anchor_followup.R` (after the existing death-vs-activity block):

   ```r
   # --- Conflicting death date analysis (161-02) ---
   death_multi <- death_raw |>
     dplyr::group_by(ID) |>
     dplyr::summarise(
       n_death_rows   = dplyr::n(),
       n_distinct_dates = dplyr::n_distinct(DEATH_DATE, na.rm = TRUE),
       .groups = "drop"
     ) |>
     dplyr::filter(n_distinct_dates > 1)

   n_conflicting <- nrow(death_multi)
   message(glue::glue("n_conflicting (>1 distinct death date): {n_conflicting}"))

   # Of conflicting patients, how many have >=1 date consistent with activity?
   # "Consistent" = death_date >= last_activity_date - 30 days
   conflicting_ids <- death_multi$ID
   death_conflict_detail <- death_raw |>
     dplyr::filter(ID %in% conflicting_ids) |>
     dplyr::left_join(
       last_activity |> dplyr::select(ID, last_activity_date),
       by = "ID"
     ) |>
     dplyr::mutate(
       consistent = !is.na(DEATH_DATE) &
         DEATH_DATE >= (last_activity_date - 30)
     )

   n_death_max_reconciles <- death_conflict_detail |>
     dplyr::group_by(ID) |>
     dplyr::summarise(any_consistent = any(consistent), .groups = "drop") |>
     dplyr::filter(any_consistent) |>
     nrow()

   message(glue::glue(
     "n_death_max_reconciles (conflicting patients with >=1 consistent date): {n_death_max_reconciles}"
   ))
   ```

   (`death_raw` and `last_activity` must already be available in the diagnostic script's environment from the existing code. Adjust variable names if the script uses different names for those objects.)

4. Update `161-CONTEXT.md` under "Diagnostic findings" with the actual numbers:
   - Fill in `n_conflicting`, `n_death_max_reconciles`, `n_death_impute_not_null`, `n_category_2a`.
   - Add a sentence confirming the 161-01 fix is reflected (DEATH_DATE_IMPUTE values now non-null).

5. Commit the updated `R/161_diag_anchor_followup.R` and `161-CONTEXT.md`.

## Acceptance criteria

- `161-CONTEXT.md` contains specific numeric values for `n_conflicting` and `n_death_max_reconciles` (no longer "pending").
- The diagnostic output confirms `DEATH_DATE_IMPUTE` is now non-NULL for at least some patients, validating the 161-01 fix.
- `n_category_2a` (imputed death dates) is recorded; previously this was indeterminate because the flag was NULL.
- The 46 zero-or-negative follow-up patients and 261 implausible-death-date patients from the original diagnostic are re-confirmed at the same counts (or any change is explained, e.g., a small shift from imputed-date reclassification).
