# 161-07 — Audit all DEATH-reading scripts for resolve_death_date() usage

**Wave:** 4
**Depends on:** 161-03
**Requires team sign-off:** no

## Goal

Find every R script in the codebase that reads from the DEATH table, determine whether each one uses or needs `resolve_death_date()`, update those that compute person-time or apply death dates to outcomes, and document explicit exemptions for scripts that only count death records without using dates.

## Steps

1. Run the codebase search to find all DEATH-reading scripts:

   ```bash
   grep -rn "DEATH" R/ --include="*.R" -l
   ```

   From the current codebase, the known scripts are (verify this list is still complete):

   - `R/00_config.R` — configuration only, no date logic
   - `R/01_load_pcornet.R` — loads raw table, no date logic
   - `R/03_duckdb_ingest.R` — ingests raw table, no date logic
   - `R/29_first_line_and_death_analysis.R`
   - `R/35_death_cause_quality.R`
   - `R/39_run_all_investigations.R` — orchestrator, no direct date logic
   - `R/51_post_death_encounter_investigation.R`
   - `R/52_gantt_v2_export.R`
   - `R/52_strange_death_source_and_enc_type.R`
   - `R/53_death_date_validation.R`
   - `R/59_death_date_summary.R`
   - `R/88_smoke_test_comprehensive.R` — updated in 161-06
   - `R/102_death_cause_nhl_flag.R`
   - `R/103_death_cause_diagnostic.R`
   - `R/142_gantt_180_export.R`
   - `R/147_surveillance_modality_frequency.R` — updated in 161-05
   - `R/161_diag_anchor_followup.R` — diagnostic only
   - `R/filter_strange_death_csvs.R`
   - `R/test_phase78_human.R`

2. For each script, open it and answer: **Does this script use DEATH_DATE to compute an endpoint (follow-up end, time-to-event, survival, or person-time)?**

   - **Yes — must use resolve_death_date():** Update the script to call `resolve_death_date()` and pass `death_date_resolved` to any endpoint computation. Follow the same pattern used in 161-05 for R/147.
   - **No — counts or descriptive only:** Add a one-line comment: `# [161-07 audit] Uses DEATH for counts/diagnostics only; resolve_death_date() not required.`
   - **No — does not apply death dates, but references DEATH_DATE for display:** Add a comment documenting this, and ensure any displayed dates come from `death_date_resolved` if a resolved object is available in scope.

3. For each script that requires updating (category "Yes"), make the minimal change:
   - Add `resolve_death_date()` call before the endpoint computation.
   - Replace raw `DEATH_DATE` references in `pmin()` / `if_else()` / survival models with `death_date_resolved`.
   - Remove the deprecated `death` argument from any `compute_followup()` calls.

4. Expected outcomes by script (preliminary — verify by reading each file):

   - `R/29_first_line_and_death_analysis.R` — likely uses death dates for time-to-event; **update**.
   - `R/35_death_cause_quality.R` — QC/diagnostic; likely counts only; **exempt**.
   - `R/51_post_death_encounter_investigation.R` — investigates post-death encounters; needs `resolve_death_date()` to define what "post-death" means; **update**.
   - `R/52_gantt_v2_export.R` — may use death date as a lifespan end; **update if endpoint**.
   - `R/52_strange_death_source_and_enc_type.R` — diagnostic; **exempt**.
   - `R/53_death_date_validation.R` — validation diagnostic; **exempt** (documents raw dates intentionally).
   - `R/59_death_date_summary.R` — summary/counts; **exempt**.
   - `R/102_death_cause_nhl_flag.R` — flags cause of death, not dates; **exempt**.
   - `R/103_death_cause_diagnostic.R` — diagnostic; **exempt**.
   - `R/142_gantt_180_export.R` — Gantt chart; uses death as a lifespan end marker; **update if endpoint**.
   - `R/filter_strange_death_csvs.R` — file filter; **exempt**.
   - `R/test_phase78_human.R` — ad-hoc test; **exempt**.

5. Produce an audit log. Create `output/161_death_audit.csv` with columns:
   `script | uses_death_date_in_endpoint | action_taken | resolve_death_date_called`

   One row per script. Write this as an `output/` CSV so it is part of the deliverable.

6. Re-run R/147 after all updates and compare per-modality counts, person-years, and rates against the pre-161 deliverable. Print a before/after comparison table to the console:

   ```r
   # Compare key metrics: n_patients, person_years, rate_per_100py for top 5 modalities
   ```

   Summarize any differences for the team (expected: small person-year increase ~0.9%, no change in modality counts for scripts that only count events without person-time).

7. Commit all modified scripts and the audit CSV.

## Acceptance criteria

- Every script in the DEATH-reading list has been assessed and either updated or explicitly exempted with a comment.
- `output/161_death_audit.csv` exists listing all scripts and their `resolve_death_date_called` status.
- No script that computes person-time or a survival endpoint uses raw `DEATH_DATE` directly after this task.
- The deprecated `death` argument warning in `compute_followup()` is not triggered by any production script after updates.
- R/147 before/after comparison is printed; any difference outside the expected ~0.9% person-year increase is flagged for team review.
- All updated scripts run without error on HiPerGator (`Rscript <script>` exits 0).
