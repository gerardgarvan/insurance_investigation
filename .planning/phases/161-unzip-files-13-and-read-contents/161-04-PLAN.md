# 161-04 — compute_followup(): shared activity, resolved death date, 3-level fu_status

**Wave:** 4
**Depends on:** 161-03
**Requires team sign-off:** D6 (posthumous diagnosis rule)

## Goal

Update `compute_followup()` in `R/utils/utils_surveillance.R` so that follow-up ends
at the earliest of the resolved death date, the last observed activity
(`get_last_activity()`), and the cutoff; apply D6; and report `fu_status` as
`positive` / `zero` / `negative` with a `fu_reason`. After this task, no retained
patient should have `follow_end < hl_anchor_date`.

## Steps

1. Read the current `compute_followup()` (≈ line 431) in full and list its callers
   (`grep -rn "compute_followup(" R/ tests/`). Keep its existing person-years formula
   and output columns; add the new columns alongside them.

2. New signature. Legacy arguments remain only until 161-07 removes their use:

   ```r
   compute_followup <- function(denominator, activity, death_resolved, cutoff,
                                last_enc = NULL, death = NULL) {
     if (!is.null(last_enc) || !is.null(death)) {
       warning("[161-04] compute_followup(): 'last_enc'/'death' are deprecated; ",
               "pass activity = get_last_activity() and death_resolved = resolve_death_date().")
     }
     if (missing(activity) || missing(death_resolved)) {
       stop("[161-04] compute_followup() requires 'activity' and 'death_resolved'.")
     }
     ...
   }
   ```

   The function no longer derives last-contact or death dates itself; both come from
   the shared utilities so R/147, R/88 and any other caller use one definition.

3. Core logic:

   ```r
   cutoff <- as.Date(cutoff)
   fu <- denominator |>
     dplyr::left_join(dplyr::select(activity, ID, last_enc_any, last_activity_any, last_observed),
                      by = "ID") |>
     dplyr::left_join(dplyr::select(death_resolved, ID, death_date_resolved, death_flag),
                      by = "ID") |>
     dplyr::mutate(
       death_flag     = dplyr::coalesce(death_flag, "no_death_record"),
       obs_end        = pmin(last_observed, cutoff),
       follow_end_raw = pmin(death_date_resolved, obs_end, cutoff, na.rm = TRUE),
       # D6: plausible death that precedes a diagnosis coded within the grace window
       posthumous_dx  = !is.na(death_date_resolved) & death_date_resolved < hl_anchor_date,
       follow_end     = dplyr::if_else(posthumous_dx, hl_anchor_date, follow_end_raw),
       fu_status      = dplyr::case_when(
         follow_end <  hl_anchor_date ~ "negative",   # regression signal; expected 0
         follow_end == hl_anchor_date ~ "zero",
         TRUE                         ~ "positive"),
       fu_reason      = dplyr::case_when(
         posthumous_dx         ~ "posthumous_dx",
         fu_status == "zero"     ~ "same_day_last_contact",
         fu_status == "negative" ~ "check_definition",
         TRUE                    ~ NA_character_)
     )
   ```

   Because the anchor is itself a DIAGNOSIS date (included in `last_observed`) and a
   plausible death date is never more than N days before `last_observed`, a death
   date earlier than the anchor can only be a D6 case. `negative` therefore occurs
   only if the anchor is after the cutoff or the activity definition diverges.

4. Person-years: compute from `follow_end` with the existing formula, floored at 0.
   Carry `death_flag`, `death_date_resolved`, `obs_end`, `fu_status`, `fu_reason`
   in the returned tibble. Remove `fu_status = "zero_or_negative"`.

5. Update the roxygen block: parameters, D2 semantics (`death_date_resolved` NA means
   no credible death; follow-up ends at `obs_end`), D6, and the three status levels.

6. Synthetic check (in an interactive session; formal tests are in 161-06). Build a
   6-patient `denominator`/`activity`/`death_resolved` set covering: positive with no
   death; plausible death after anchor; implausible death (NA resolved, follows to
   last activity); inpatient anchor with later discharge; same-day last contact
   (zero); posthumous diagnosis (D6). Confirm each `fu_status`/`fu_reason`.

7. Full-cohort check on HiPerGator using the 161-03 driver objects:

   ```r
   fu <- compute_followup(cohort, activity, death_resolved, CUTOFF_DATE)
   dplyr::count(fu, fu_status, fu_reason)
   sum(fu$person_years)
   ```

## Acceptance criteria

- `compute_followup()` takes `activity` and `death_resolved`; it contains no
  admit-only `last_enc_date` logic and no raw DEATH_DATE use.
- Full-cohort run: `fu_status == "negative"` count is 0.
- The 44 death-before-anchor patients have `death_flag` in
  {`implausible_post_activity`, `conflicting_unresolved`, `conflicting_resolved`},
  `fu_status == "positive"`, and none has `death_date_resolved < hl_anchor_date`
  unless flagged `posthumous_dx`.
- The 2 inpatient same-day cases have `fu_status == "positive"` (≈ 8 days).
- Total person-years within ±1% of `person_years_projected_d2` from 161-02
  (difference expected only from D3 source priority on conflicting patients);
  any larger difference is explained before proceeding.
- Legacy arguments emit a deprecation warning; missing new arguments stop with a clear message.
