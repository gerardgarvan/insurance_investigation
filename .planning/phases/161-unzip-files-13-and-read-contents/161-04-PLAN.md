# 161-04 — Redefine compute_followup(): obs_end + resolved death date + 3-level fu_status

**Wave:** 3
**Depends on:** 161-03
**Requires team sign-off:** no

## Goal

Update `compute_followup()` in `R/utils/utils_surveillance.R` to replace admit-only `last_enc_date` with `obs_end` (latest of discharge or admit date plus any CDM activity), use `death_date_resolved` from `resolve_death_date()` instead of raw `death_date`, and split `fu_status` from 2 levels into 3 (`positive` / `zero` / `negative`), ensuring no retained patient can have `follow_end < hl_anchor_date`.

## Steps

1. Open `R/utils/utils_surveillance.R`. Locate `compute_followup()` (signature at line 431). Read the full function before editing.

2. Update the function signature to accept a `death_resolved` argument (the output of `resolve_death_date()`) instead of the raw `death` table. Keep the old `death` parameter name as a deprecated alias with a warning if passed, to avoid breaking callers before 161-07 finishes the audit:

   ```r
   compute_followup <- function(denominator, last_enc, cutoff,
                                death_resolved = NULL,
                                death = NULL) {   # deprecated; use death_resolved
     if (!is.null(death) && is.null(death_resolved)) {
       warning("[161-04] 'death' arg is deprecated in compute_followup(); pass death_resolved instead.")
       # Minimal shim: treat as before (will be removed after 161-07 audit)
       death_resolved <- death |>
         dplyr::filter(!is.na(DEATH_DATE)) |>
         dplyr::group_by(ID) |>
         dplyr::summarise(death_date_resolved = min(DEATH_DATE),
                          death_flag = "plausible", .groups = "drop")
     }
     ...
   }
   ```

3. Replace the `last_enc_date` derivation (currently takes `min(ADMIT_DATE)` or similar) with `obs_end`:

   ```r
   obs_end <- last_enc |>
     dplyr::group_by(ID) |>
     dplyr::summarise(
       obs_end = max(
         pmax(ADMIT_DATE, DISCHARGE_DATE, na.rm = TRUE),
         na.rm = TRUE
       ),
       .groups = "drop"
     )
   ```

   `DISCHARGE_DATE` must be present in `last_enc` (it is already available in the ENCOUNTER table). Cap `obs_end` at `cutoff` after computing the max:

   ```r
   obs_end <- obs_end |>
     dplyr::mutate(obs_end = pmin(obs_end, cutoff, na.rm = TRUE))
   ```

4. Replace the `pmin(death_date, last_enc_date, cutoff, na.rm = TRUE)` line with:

   ```r
   follow_end = pmin(
     death_date_resolved,   # from death_resolved (NA if no plausible death date)
     obs_end,
     cutoff,
     na.rm = TRUE
   )
   ```

   Join `death_resolved` (columns: ID, `death_date_resolved`, `death_flag`) and `obs_end` to `denominator` before computing `follow_end`.

5. Replace the 2-level `fu_status` with 3-level (per D5):

   ```r
   fu_status = dplyr::case_when(
     is.na(follow_end)              ~ "no_followup_date",
     follow_end < hl_anchor_date    ~ "negative",       # should not occur after fix
     follow_end == hl_anchor_date   ~ "zero",
     TRUE                           ~ "positive"
   )
   ```

   Note: `negative` cases should be 0 after the fix. Keep the level so the assertion in 161-06 can detect regressions.

6. Carry `death_flag` through to the function's return value by adding it to the output `select()` call.

7. Update the roxygen comment block at the top of `compute_followup()` to document the new parameters and the three `fu_status` levels.

8. Run a local smoke test by sourcing the updated utils file and calling `compute_followup()` with a small synthetic tibble (5 patients: 1 positive, 1 zero, 1 with implausible death date, 1 with no death record, 1 with conflicting-resolved death date). Confirm the three `fu_status` levels appear as expected and `death_flag` is present in the output.

## Acceptance criteria

- `compute_followup()` accepts `death_resolved` (output of `resolve_death_date()`) and uses `death_date_resolved` in `pmin()`.
- `obs_end` uses `pmax(ADMIT_DATE, DISCHARGE_DATE, na.rm = TRUE)` capped at cutoff — not admit-only.
- `fu_status` has exactly three levels in the output: `positive`, `zero`, `negative` (plus the legacy `no_followup_date` for patients with no dates at all).
- `death_flag` is present in the function's return value.
- No patient in the output has `follow_end < hl_anchor_date` when `fu_status != "negative"`.
- The deprecated `death` argument emits a warning but does not error, preserving backward compatibility until 161-07 completes.
- Total person-years from a full run increases by approximately 0.9% relative to the pre-fix run (39,107 -> ~39,460 person-years, per the diagnostic finding in 161-CONTEXT.md).
