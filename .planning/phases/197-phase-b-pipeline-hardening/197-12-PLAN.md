# 197-12: R/109 stale-global regression fix + verification protocol

## Decisions

**D-197-12-01**: Stale session objects can silently mask missing variables.
- Root cause: `run()` / `source(..., local = new.env(parent = globalenv()))` does NOT
  isolate against objects already present in globalenv from a prior interactive run.
- Phase 196 renamed `before`/`after` to `chemo_before`/`chemo_after` throughout R/109,
  but missed one reference: Section 7, line ~288, `after_first <- after %>%`.
- On 11/11 this did not error because a stale `after` from a prior session run existed
  in globalenv. The Section 7 output (D-04 timing shift) used that stale data.
- Fix: (a) `rm(list = intersect(ls(), c("before", "after")))` guard added after the
  setup block to evict any stale object immediately; (b) line ~288 corrected to
  `chemo_after %>%`.

**D-197-12-02**: Delivered-output scripts must be verified in a fresh R process.
- Use `Rscript -e 'source("R/<NNN>.R")'` or `R --no-save --no-restore --vanilla`
  per script. Never reuse a session across scripts.
- 197-RERUN-VERIFICATION.md updated: session setup section now mandates fresh process
  and explains why source(..., local = new.env(...)) is insufficient.
