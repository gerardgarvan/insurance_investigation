# 197-10: Staged treatment_episodes chain — R/26→stage1→R/28→stage2→R/53→R/29→canonical

## Decisions

**D-197-01** (prior): R/29 is the sole canonical writer of `treatment_episodes.rds`.

**D-197-10-01**: Explicit staged file chain.
- R/26 → `treatment_episodes_stage1.rds` (raw episodes, 12 R/26 columns)
- R/28 reads stage1 → writes `treatment_episodes_stage2.rds` (enriched, +11 R/28 columns)
- R/53 reads stage2 → writes `validated_death_dates.rds`
- R/29 reads stage2 + validated_death_dates → writes canonical `treatment_episodes.rds` (+`is_first_line`)
- Run order enforced in R/39: 26 → 28 → 53 → 29
- R/28 uses `getOption("p143_out_rds", ...)` for the output path; the 180-day pass sets it explicitly in R/39.

**D-197-10-02**: Validate-then-write (atomic) in R/28 and R/29.
- Build object in memory; run all guards; write to `<target>.tmp`; rename over target only on success.
- Prevents a failed mid-write from truncating the target file.

**D-197-10-03**: Guard key corrected to `(patient_id, treatment_type, episode_start)`.
- Same-day episodes of different treatment types (e.g., Chemotherapy + Immunotherapy on the same date) are clinically valid distinct rows.
- Old key `(patient_id, episode_start)` produced 1,643 false duplicates.

**D-197-10-04**: R/29 `stop()` on missing R/28 enrichment columns.
- Required columns: `regimen_label`, `drug_names`, `cancer_category`, `cancer_link_method`, `is_hodgkin`, `triggering_code_description`, `drug_group`.
- Replaces the prior `warning()` + silent NA-fill pattern that allowed first-line = 0 to pass undetected.

**D-197-10-05**: R/29 pre-write validation includes `is_first_line > 0` guard.
- Catches a re-regression where stage1 (lacking regimen_label) is supplied instead of stage2.
