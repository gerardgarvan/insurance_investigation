# Plan 197-01 — Run Order: R/39 + SCRIPT_INDEX

## Objective

The dependency audit confirmed two run-order bugs and one dual-writer problem:
- R/29 appears before R/53 in R/39, but R/29 requires `validated_death_dates.rds` produced by R/53.
- Both R/26 and R/29 write `treatment_episodes.rds`; R/29's version (with `is_first_line`) is the
  required artifact for all downstream consumers.
- R/14 internally calls R/02, so running both in a rerun list runs R/02 twice.

Decision D-197-01: R/29 is sole final writer; R/26 writes `treatment_episodes_stage1.rds`.

## Tasks

### Task 0 — Context
Probe files needed:
- `R/39_run_all_investigations.R` — lines containing R/26, R/29, R/02, R/14, R/53
- `R/26_treatment_episodes.R` — where it writes treatment_episodes.rds
- `R/29_treatment_episodes_refine.R` — where it reads/writes treatment_episodes.rds
- `R/SCRIPT_INDEX.md` — entries for R/26, R/29, R/53, R/02, R/14
- Rerun template: search for RERUN-AND-REISSUE.md

Use `grep -n` to find exact lines; read only those ranges.

### Task 1 — Swap R/29 and R/53 in R/39

Find the lines where R/29 and R/53 are sourced. R/53 must precede R/29.
Make the swap. Add a comment above R/53: `# R/53 must run before R/29 (validated_death_dates.rds)`.

### Task 2 — Single owner for treatment_episodes.rds

In `R/26_treatment_episodes.R`:
- Change the output variable name / path so it writes `treatment_episodes_stage1.rds` instead of
  `treatment_episodes.rds`.
- Add a `message()` checkpoint: `"[R/26] treatment_episodes_stage1.rds written — N rows"`.
- Do NOT touch any logic or columns; only change the write path.

In `R/29_treatment_episodes_refine.R`:
- Change the read at the top to read `treatment_episodes_stage1.rds` (from R/26).
- Confirm R/29 already writes `treatment_episodes.rds` as final output. If not, add the write.
- Add a `message()` checkpoint noting it is the canonical writer.

Add a comment at the R/26 write call: `# Intermediate; R/29 writes the canonical treatment_episodes.rds`.

### Task 3 — Column guard for is_first_line

In `R/142` (Gantt builder), `R/110` (payer breakdown), `R/100`:
- Add `stopifnot("is_first_line" %in% names(episodes))` right after loading treatment_episodes.rds.
- If the file variable name differs, adapt to match.

Use grep to find exact load lines before adding the guard.

### Task 4 — Remove R/02 from rerun lists that include R/14

Search for RERUN-AND-REISSUE.md and any runner helper that lists both R/02 and R/14.
In each found location: remove R/02 from the list when R/14 is present, adding a comment:
`# R/14 sources R/02 internally — do not list both`.

Also check R/39 for any block that sources both R/02 and R/14 consecutively; apply the same fix there.

### Task 5 — SCRIPT_INDEX updates

Update `R/SCRIPT_INDEX.md`:
- R/26 entry: document that it writes `treatment_episodes_stage1.rds` (intermediate).
- R/29 entry: document that it is the canonical writer of `treatment_episodes.rds`;
  depends on R/26 (stage1) and R/53 (validated_death_dates.rds).
- R/53 entry: add note that R/29 must run after it in R/39.
- R/02 / R/14 entries: add note that R/14 calls R/02 internally; do not list both in rerun.
