### 3. Drive-Time Proxy

Drive-time thresholds (e.g., "more than 60 minutes to the nearest oncology center") are
a separate approach used in some access studies. This pipeline does not currently compute
drive time — it uses straight-line ZIP5 centroid distance. A drive-time component could
be added in a later phase if the team determines that geographic barriers (traffic, roads)
matter more than raw distance for this cohort. No numbers are available here; this family
is noted for completeness.

---

## Shape of Decision

The team should decide between two structural options:

**Option A — Single cutoff.** One binary flag (`far_from_care = 1` when distance ≥ X).
Simplest to communicate; appropriate when a single threshold can be defended (e.g., by
citation or programmatic definition from a payer's network standard).

**Option B — Categorical bands.** Multiple mutually exclusive bands (e.g., 0–30 mi,
30–50 mi, >50 mi). More granular; useful if the team expects a dose-response relationship
between distance and outcome that a binary flag would obscure.

Either shape can be implemented as a config change. The current implementation supports
Option A via `CONFIG$distance_cutoff_mi`. Option B would require a minor SECTION 12
extension in a follow-up phase.
