# Phase 192.3: Distance >100 mi vs CBC Stratified by SOURCE (Medicare Reassigned to Address Source) — Context

**Gathered:** 2026-11-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Re-run the existing far-from-care (>100 mi) × CBC association (R/165_distance_cbc_association.R /
utils_distance_cbc.R) with a SOURCE stratification layer. Medicare-sourced encounters are
reassigned to the SOURCE of the patient's LDS_ADDRESS_HISTORY row in effect at ADMIT_DATE
(same backward rule as get_zip9_at_date()), with a modal non-Medicare encounter SOURCE fallback,
and "Medicare_unresolved" as the terminal label. New sheets are added to the distance-CBC
workbook. R/181 (year-1 CBC × distance) gets the same treatment as a separate Plan 03.

Three plans total:
- **Plan 01** — Step-0 discovery probe (must run on HiPerGator before Plan 02 is written)
- **Plan 02** — R/165 SOURCE stratification + new workbook sheets
- **Plan 03** — R/181 SOURCE stratification + new workbook sheets

Plan 02 and Plan 03 are blocked on Plan 01 results. D-192.3-01 and D-192.3-02 must be resolved
(Medicare SOURCE values confirmed; LDS SOURCE values confirmed) before planning proceeds.

</domain>

## Implementation Decisions

### Plan 01 — Step-0 Discovery Probe

- **D-01:** Plan 01 is a pure discovery script (run interactively: `source("R/...", local = new.env(parent = globalenv()))` under `module load R/4.5`). No RDS, no workbook output.
- **D-02:** Console output is a compact, paste-ready block containing:
  1. ENCOUNTER SOURCE frequency table for the HL cohort (counts <11 suppressed as "<11") — identifies Medicare SOURCE value(s) → CONFIG$medicare_source_codes
  2. Column list for LDS_ADDRESS_HISTORY (confirmed present by user; step-0 confirms the actual SOURCE values in that table)
  3. Count of encounters in the far/CBC analysis set that are Medicare-sourced
  The user pastes this output back; values are recorded in 192.3-01-SUMMARY.md as the
  authoritative source for D-192.3-01 and D-192.3-02.
- **D-03 (blockers):** Plan 02 cannot be written until BOTH are resolved:
  - D-192.3-01: CONFIG$medicare_source_codes populated from the freq table
  - D-192.3-02: LDS_ADDRESS_HISTORY SOURCE values confirmed (column is present — user confirmed — values TBD from step-0)
  If step-0 reveals other claims sources (e.g. Medicaid), list them as a team decision rather
  than adding them to CONFIG$medicare_source_codes automatically.

### SOURCE Reassignment Logic — assign_analytic_source()

New helper in `R/utils/utils_distance_cbc.R`.

- **D-04:** Columns added per encounter:
  - `SOURCE_raw` — original ENCOUNTER.SOURCE value (kept, never modified)
  - `SOURCE_analytic` — the reassigned value used for all stratification
  - `source_reassigned` — 0/1 flag (1 = Medicare row that received a new SOURCE_analytic)
  - `source_reassign_method` — one of: `"not_reassigned"` (non-Medicare), `"address"`, `"modal_encounter"`, `"unresolved"`

- **D-05 — Reassignment chain (applies when SOURCE_raw is in CONFIG$medicare_source_codes):**
  1. **Address lookup:** Set SOURCE_analytic to the SOURCE of the LDS_ADDRESS_HISTORY row in
     effect at ADMIT_DATE (same backward rule as get_zip9_at_date(): exact period match, then
     most recent row before ADMIT_DATE). If that SOURCE is also in CONFIG$medicare_source_codes,
     proceed to step 2.
  2. **Modal non-Medicare encounter SOURCE:** Use the patient's modal SOURCE_raw across their
     **whole record** (all non-Medicare ENCOUNTER rows, not just the analysis window); ties broken
     by most recent encounter. If no non-Medicare encounters exist, proceed to step 3.
  3. **Unresolved:** SOURCE_analytic = `"Medicare_unresolved"`. Kept and reported; not dropped.
  
  `source_reassign_method` records which step resolved the row.

- **D-06:** Plumb `assign_analytic_source()` into `build_enc_analysis()` immediately after Step 2
  (the ENCOUNTER join), before far/CBC flags are computed. All downstream code uses
  SOURCE_analytic for stratification.

- **D-07:** Patient-level SOURCE (for BY_SOURCE_pat sheets): modal SOURCE_analytic across the
  patient's encounters in the analysis window, ties broken by most recent encounter.

### Output Sheets — R/165 Workbook (Plan 02)

New dated file `distance_cbc_association_<YYYYMMDD>.xlsx`. All existing sheets regenerated
(regression check required — see D-11). KEY stays leftmost.

New sheets added:
- `BY_SOURCE_enc` — per SOURCE_analytic, 2×2 of far × CBC; row %; chi-square (Fisher when
  expected < 5); Woolf OR via naive_or_se(). Both windows (whole record and post-anchor)
  reported side by side.
- `BY_SOURCE_pat` — same at patient level.
- `BY_SOURCE_enc_addr` — sensitivity: same structure as BY_SOURCE_enc, same denominator (all
  encounters), but `modal_encounter`-reassigned rows become `"Medicare_unresolved"` instead.
  Only address-based reassignment counts. KEY must include a plain-language explanation of the
  difference between BY_SOURCE_enc and BY_SOURCE_enc_addr.
- `BY_SOURCE_pat_addr` — same sensitivity at patient level.
- `SOURCE_REASSIGN_QC` — counts by source_reassign_method (not_reassigned, address,
  modal_encounter, unresolved); number and % of Medicare encounters reassigned; number unresolved.
- Mantel–Haenszel pooled OR across SOURCE_analytic strata + Breslow–Day homogeneity test,
  as a summary line in BY_SOURCE_enc and BY_SOURCE_pat.
- `<11` suppression via suppress_display() on all count cells.

### Output Sheets — R/181 Workbook (Plan 03)

Separate dated workbook for R/181 (`cbc_prior_year_<YYYYMMDD>.xlsx` or equivalent).
Same new sheet structure as R/165 (BY_SOURCE_enc, BY_SOURCE_pat, _addr variants,
SOURCE_REASSIGN_QC, MH pooled OR + Breslow–Day). KEY leftmost.

R/181 patient-level SOURCE: modal SOURCE_analytic across encounters in the year-1 window;
ties broken by most recent. If a patient has no encounters in the window, fall back to the
whole-record modal SOURCE_analytic.

Plan 03 blocked on Plan 01 (same blockers as Plan 02).

### Regression Check (Plans 02 and 03)

- **D-11:** Pre-existing sheets in the new workbook must match the prior workbook
  (distance_cbc_association_20261008.xlsx for R/165; R/181's latest prior dated workbook)
  on: same Ns, same ORs, same p-values. If upstream data changed since the prior run, log the
  differences in the QC sheet rather than treating them as failures. Regression check is a
  required task in both Plan 02 and Plan 03.

### R/181 Inclusion

- **D-08:** R/181 is included in this phase as Plan 03, after Plan 02. Reuses
  assign_analytic_source() at encounter level. Produces its own dated workbook.
- **D-09:** Plan 03 is not written until Plan 01 step-0 results are in hand (same blockers
  as Plan 02).

### Config and Naming

- **D-10:** Medicare SOURCE values live in `CONFIG$medicare_source_codes` (populated after
  Plan 01). Code never hardcodes the Medicare SOURCE string. If step-0 reveals other claims
  sources, they become a team decision before being added to config.

### Claude's Discretion

- Exact function signature for assign_analytic_source() (inputs: enc tibble with SOURCE_raw,
  addr tibble, config list; output: enc with four new columns)
- Whether assign_analytic_source() loads LDS_ADDRESS_HISTORY internally or accepts it as an
  argument (prefer argument injection for testability — same seam as get_zip9_at_date()'s
  addr_full parameter)
- R script number for the Plan 01 probe (check SCRIPT_INDEX before assigning)
- Sheet column layout within the BY_SOURCE_enc/pat structure
- Whether Breslow–Day appears as a row within the BY_SOURCE sheets or as a separate sub-table

### Reusable Assets
- `build_enc_analysis()` (utils_distance_cbc.R:182): already carries SOURCE through the
  ENCOUNTER join at Step 2 (~line 198). assign_analytic_source() slots in immediately after
  Step 2 — no structural change to build_enc_analysis() required beyond adding the call.
- `get_zip9_at_date()` (utils_address.R:133): the addr_full injection seam and backward-lookup
  logic are the direct template for the address SOURCE lookup in assign_analytic_source().
- `modal_source_fn()` (R/165:~345): computes modal SOURCE with recency tiebreak — reusable
  for the modal non-Medicare encounter SOURCE fallback and the patient-level aggregation.
- `naive_or_se()`: already used in R/165 for Woolf OR; reuse in BY_SOURCE sheets.
- `suppress_display()`: established pattern; apply to all count cells in BY_SOURCE sheets.

### Established Patterns
- Output files: `glue("..._<Sys.Date()>.xlsx")` with openxlsx; KEY sheet leftmost; UF colors
  #0021A5 (blue) and #FA4616 (orange).
- Config-driven cutoffs: CONFIG$far_from_care_cutoff_mi = 100 (D-14 from Phase 165).
- Two analysis windows always reported side-by-side: whole record and post-anchor
  (hl_anchor_date, anchor day = pre, as R/147).
- testthat fixtures in tests/testthat/ — new helper needs unit tests (non-Medicare unchanged;
  Medicare → address SOURCE; Medicare with no non-claims address → modal encounter fallback;
  modal encounter fallback → unresolved; address change mid-period picks in-effect row).

### Integration Points
- assign_analytic_source() reads LDS_ADDRESS_HISTORY (via addr_full seam or direct load);
  joins to enc tibble on ID + ADMIT_DATE using the backward-lookup rule.
- Whole-record modal SOURCE fallback requires all ENCOUNTER rows for a patient, not just the
  analysis-window subset — ensure the full enc tibble (pre-filter) is available to the helper.

<specifics>
## Specific Ideas

- **Plan 01 paste-ready block format:** Print a single clearly delimited block to console
  (e.g., with cat("===BEGIN STEP0 OUTPUT===\n"..."\n===END STEP0 OUTPUT===\n")) so the user
  can paste it back in full without ambiguity.
- **source_reassign_method column:** Four values only — "not_reassigned", "address",
  "modal_encounter", "unresolved" — stored as character, not factor, for easy openxlsx export.
- **BY_SOURCE_enc_addr vs BY_SOURCE_enc difference:** The _addr sheets keep the same
  denominator (all encounters). Only the reassignment rule changes: rows whose
  source_reassign_method == "modal_encounter" become "Medicare_unresolved" in the _addr version.
  Non-Medicare and address-reassigned rows are identical across both versions.
- **Regression check:** Compare Ns, ORs, and p-values from KEY/A_crosstab/B_test sheets of
  the new workbook against the pinned prior workbook path (env var R1923_PRIOR_DIST_CBC_WB or
  similar). Log differences in QC sheet; do not stop on differences if upstream data has
  changed since the prior run.
