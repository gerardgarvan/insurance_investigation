<objective>
Implement 140-CONTEXT.md Section 5's recommendation: carry ZIP5 forward without a hard time-window cap, and write the elapsed gap-days into the analytic dataset as a covariate rather than a discard rule (P-04a). Add a diagnostic mechanism for Section 5's second finding -- the non-monotonic ZIP5 accuracy result (52.0% at 181-365 days rising to 56.1% at 366+) -- so a real HiPerGator run can determine whether this is a composition effect (e.g. very-stable long-tenure patients dominating the 366+ bin) or a binning artifact (P-04b).

Per 140-08-PATCH FIX-01/FIX-02: this plan produces TWO independently-computed gap columns, not one. 140-04 produces `scenario_assigned` (forward-inclusive) and `scenario_assigned_backward_only` -- which record resolved an encounter DIFFERS between the two specifications (a forward-only S2 encounter is resolved under forward-inclusive and unresolvable under backward-only), so a single gap column cannot represent both without being NA for 92% of the largest resolved bucket (201,118 of 217,570 S2 encounters are forward-only). `gap_days_at_assignment` (forward-inclusive) and `gap_days_at_assignment_backward_only` are computed via separate reductions over `s1_matches`/`s2_matches`, mirroring 140-04's own treatment of the two waterfalls. Per 140-08-PATCH FIX-08, the either-direction reductions (`s1_nearest_any`, `s2_nearest_any`) break exact ties in favor of the backward candidate, since leaving an exact-tie resolution to row order is not a detail this covariate's defensibility can afford to leave unspecified.

Purpose: median gap between ZIP9 changes is 547 days (p25 184, p75 1,310); only ~22% of gap observations fall under 180 days. A 90/180/365-day cap would strand the majority of encounters for little accuracy gain -- ZIP5 accuracy flattens around 52-57% past 90 days with no decay cliff justifying a cutoff. Recency becomes a sensitivity analysis (via the two gap columns) rather than a discard rule, which 140-CONTEXT.md calls "the more defensible posture under review."

If D-1 (140-01 Task 2) returned option-b, this plan still executes (its output is diagnostic), but no workbook produced by this phase ships until D-1 resolves.

This plan depends on 140-04 (not just for file-conflict avoidance -- both gap columns should reflect the FINAL, collapsed `scenario_assigned`/`scenario_assigned_backward_only` columns 140-04 produces, since which address record "resolved" an encounter under EACH specification is what determines that specification's gap). If 140-04's Task 1 was skipped (D-2 = option-b, no dual-mode assignment built), this plan computes `gap_days_at_assignment` only (the single-specification case) and `gap_days_at_assignment_backward_only` is not built -- record this explicitly in the SUMMARY rather than silently producing a column with no corresponding scenario specification behind it.

Output: `gap_days_at_assignment` (forward-inclusive, signed, per-encounter) and `gap_days_at_assignment_backward_only` (backward-only, signed, never-negative) both added to `encounter_zip`, each independently computed; `median_gap_within_bin` added to `validation_curve`; a recorded D-3 decision confirming the uncapped-carry-forward design already implemented by this phase's other plans.
</objective>

After `s1_matches` is computed (~line 853-859), add the four reductions FIX-01/FIX-02/FIX-08 require -- two per side (nearest-either-direction with backward-wins-ties, and nearest-backward-only):

```r
# 140-08-PATCH FIX-01/FIX-08: nearest zip9_seq spell in EITHER direction, for the
# forward-inclusive S3 gap covariate, with backward-wins-ties tiebreaking. Independent
# from the backward-only reduction below -- two reductions, not one reused for both.
s1_nearest_any <- s1_matches %>%
  mutate(
    gap_signed = as.numeric(ADMIT_DATE - period_start_dt),
    .tie_rank  = if_else(gap_signed >= 0, 0L, 1L)   # FIX-08: backward wins exact ties
  ) %>%
  group_by(ID, ENCOUNTERID, ADMIT_DATE) %>%
  arrange(abs(gap_signed), .tie_rank, .by_group = TRUE) %>%
  slice_head(n = 1) %>%
  ungroup() %>%
  select(ID, ENCOUNTERID, ADMIT_DATE, gap_days_s3_any = gap_signed)

# 140-08-PATCH FIX-02: nearest BACKWARD-ONLY zip9_seq spell, for the backward-only S3
# gap covariate. All candidates here have gap_signed >= 0 by construction (direction ==
# "backward" means period_start_dt <= ADMIT_DATE), so "nearest" is simply the minimum.
s1_nearest_backward <- s1_matches %>%
  filter(direction == "backward") %>%
  mutate(gap_signed = as.numeric(ADMIT_DATE - period_start_dt)) %>%
  group_by(ID, ENCOUNTERID, ADMIT_DATE) %>%
  slice_min(gap_signed, n = 1, with_ties = FALSE) %>%
  ungroup() %>%
  select(ID, ENCOUNTERID, ADMIT_DATE, gap_days_s3_bwd = gap_signed)
```

```r
encounter_zip <- encounter_zip %>%
  left_join(s2_nearest_backward %>%
              transmute(ID, ENCOUNTERID, ADMIT_DATE,
                        gap_days_s2_bwd = as.numeric(ADMIT_DATE - period_start_dt)),
            by = c("ID", "ENCOUNTERID", "ADMIT_DATE")) %>%
  left_join(s2_nearest_any,      by = c("ID", "ENCOUNTERID", "ADMIT_DATE")) %>%
  left_join(s1_nearest_backward, by = c("ID", "ENCOUNTERID", "ADMIT_DATE")) %>%
  left_join(s1_nearest_any,      by = c("ID", "ENCOUNTERID", "ADMIT_DATE")) %>%
  mutate(
    # Forward-inclusive: nearest resolving record in either direction, signed.
    gap_days_at_assignment = case_when(
      has_direct_zip9        ~ as.numeric(ADMIT_DATE - direct_zip_period_start),
      !is.na(gap_days_s2_any) ~ gap_days_s2_any,
      !is.na(gap_days_s3_any) ~ gap_days_s3_any,
      TRUE                    ~ NA_real_
    ),
    # Backward-only: backward matches only. Never negative by construction.
    gap_days_at_assignment_backward_only = case_when(
      has_direct_zip9        ~ as.numeric(ADMIT_DATE - direct_zip_period_start),
      !is.na(gap_days_s2_bwd) ~ gap_days_s2_bwd,
      !is.na(gap_days_s3_bwd) ~ gap_days_s3_bwd,
      TRUE                    ~ NA_real_
    )
  ) %>%
  select(-gap_days_s2_bwd, -gap_days_s2_any, -gap_days_s3_bwd, -gap_days_s3_any)
```
