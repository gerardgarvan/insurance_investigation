<objective>
Implement 140-CONTEXT.md Section 5's recommendation: carry ZIP5 forward without a hard time-window cap, and write the elapsed gap-days into the analytic dataset as a covariate rather than a discard rule (P-04a). Add a diagnostic mechanism for Section 5's second finding -- the non-monotonic ZIP5 accuracy result (52.0% at 181-365 days rising to 56.1% at 366+) -- so a real HiPerGator run can determine whether this is a composition effect (e.g. very-stable long-tenure patients dominating the 366+ bin) or a binning artifact (P-04b).

Purpose: median gap between ZIP9 changes is 547 days (p25 184, p75 1,310); only ~22% of gap observations fall under 180 days. A 90/180/365-day cap would strand the majority of encounters for little accuracy gain -- ZIP5 accuracy flattens around 52-57% past 90 days with no decay cliff justifying a cutoff. Recency becomes a sensitivity analysis (via gap_days_at_assignment) rather than a discard rule, which 140-CONTEXT.md calls "the more defensible posture under review."

This plan depends on 140-04 (not just for file-conflict avoidance -- gap_days_at_assignment should reflect the FINAL, collapsed scenario_assigned/scenario_assigned_backward_only columns 140-04 produces, since which address record "resolved" an encounter is what determines the gap).

Output: `gap_days_at_assignment` (signed, per-encounter) added to `encounter_zip`; `median_gap_within_bin` added to `validation_curve`; a recorded D-3 decision confirming the uncapped-carry-forward design already implemented by this phase's other plans.
</objective>
