## Goal

`R/03_duckdb_ingest.R` superassigns `ingest_log` (line 199) and `tables_ingested`
(line 207) from inside a `tryCatch` expression argument, which evaluates in the sourced
script's new.env. `<<-` therefore begins its search at parent.env(new.env) = globalenv and
skips the local bindings created at lines 114 and 130. Convert both to `<-`. Preserve the
superassignment at line 181, which is correct.

**Why line 199 matters.** Its failure is currently masked: R/03 aborts at ~line 371 before
reaching line 375 (`readr::write_csv(ingest_log, log_path)`) and line 385
(`Tables: {nrow(ingest_log)}`). Fixing line 207 alone lets the script run further and
produce a zero-row ingest log reporting `Tables: 0, Total rows: 0`.

**Why line 181 must not change.** A function literal passed as `error =` is evaluated in
new.env, so its closure environment is new.env and `<<-` from inside it searches new.env
first — finding the `df` created at line 150. `<-` would bind in the handler frame and
discard the sanitised columns, breaking the retry that succeeded on LAB_RESULT_CM
(log2.txt line 349).

**Do NOT change:** R/39's `source(script, local = new.env(parent = globalenv()))` (D-05).

**Cascades resolved:** none directly, but see D-13 — R/03 will begin promoting a fresh
database mid-run, and index creation will resume.
