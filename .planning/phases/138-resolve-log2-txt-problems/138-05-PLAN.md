# Plan 138-05: Diagnose R/52 / R/101 / R/104 "cannot open the connection"

**Phase:** 138 — resolve log2.txt problems
**Wave:** 1 (independent — diagnosis only)
**Requirements:** D-10, D-11, D-12

## Goal

Identify the actual missing artefact behind three of the nine log2.txt failures. The
previously assumed cause (missing `validated_death_dates.rds`) is disproved.

## Context

R/52 (log line 3760), R/101 (2159) and R/104 (2293) all fail with a bare
"cannot open the connection" — an R `file()` error carrying no path.

Disproving the assumed cause: `validated_death_dates.rds` exists and loads after R/53
fails, at log lines 1348 (R/59) and 1412 (R/51), both reporting 1344 patients.

Ordering constraint (D-11): R/101 and R/104 run in Stage 2; R/52 runs in Stage 4. Any
artefact R/52 produces is unavailable to them within the same run.

## Steps

### Step 1 — Enumerate file reads
Grep R/52, R/101 and R/104 for `readRDS|read_csv|read\.csv|readLines|file\(|fromJSON|
read_excel` and list every path constructed.

### Step 2 — Resolve each path against disk
Check each against `CONFIG$cache$*` and `output/`. Identify which do not exist.

### Step 3 — Determine the producer
For each missing artefact, find the script that writes it and its stage position in the
R/39 SCRIPT_INDEX.

### Step 4 — Classify
Either (a) the producer failed for a reason already covered by 138-01/02/03, (b) the
producer runs too late (D-11 → reorder), or (c) a fourth independent root cause.

### Step 5 — Add named assertions (D-12)
Wrap each file read in the existing `assert_*_exists()` convention (see R/03 line 147) so
the next occurrence names the file.

## Verification

- Each of R/52, R/101, R/104 has a documented missing artefact and an attributed producer.
- Grep each for `assert_` — at least one call per file read.
- Re-run: failures either resolve or fail with a path-naming message.
