<objective>
Build a section-by-section crosswalk from every item in `AnalyticManual_2026.01.30.md` to repo
evidence. Each item gets a stable ID and a status. The map also catalogs repo domains the manual
does not mention yet (AM-MAP-02) and records team decisions (AM-MAP-03).

The map keeps three things separate on every row: **what the manual says** (Manual Text), **what
the repo has** (Repo Source + Evidence Type + What the Source Shows), and **what the team approved**
(Decision ID). Phase 190 identifies evidence leads; it does not issue verdicts. A matching function
or config key is recorded as a lead for Phase 191, not as proof the rule is implemented.

No manual text and no pipeline code changes in this phase. The only new code is the
evidence-map tool under `tools/am_evidence/`.
</objective>

<definitions>

## Item statuses (evidence-map rows)

| Status | Use when |
|--------|----------|
| `FILLED-NEEDS-CHECK` | The manual contains a substantive rule or statement that can be checked against the repo |
| `EMPTY-REPO-CAN-ANSWER` | The manual field is empty (or the domain is repo-only) and the repo has a source that can answer it |
| `EMPTY-NEEDS-TEAM` | Empty or unresolved, and only team input can answer it (e.g., pending Sharon) |
| `OUT-OF-SCOPE` | Guidance/boilerplate text, sign-off boxes, title/grant with no repo source |
| `BLOCKED` | Depends on an input that has not been received (c0 → OneFLquestions document) |
| `RETIRED` | Lifecycle state only, never assigned in Phase 190. A retired row keeps its ID; its prior status is recorded in Notes as `was: <STATUS>` |

A row whose only evidence is `PLANNING-DOC` keeps its status but has `PROVISIONAL` at the start of
Notes. Phase 191/192 must locate code or config before relying on it.

## Evidence types (Evidence Type column; multiple allowed, `; `-separated)

`CODE` (current executable code: `path:function()` and line range) · `CONFIG` (`R/00_config.R:KEY`)
· `PLANNING-DOC` (phase SUMMARY/CONTEXT/DISCUSSION-LOG) · `TEAM-DECISION` (attributed decision,
linked via Decision ID) · `MEETING-NOTES` (`TeamMtgNotes2026.md` with date) · `NONE`

## Decision statuses (AM-MAP-03 table only)

`OPEN` · `CONFIRMED` (decision stated and in force) · `SUPERSEDED` (replaced by a later decision;
Notes name the replacement)

## ID scheme

- Pattern: `S{section}-{DOMAIN}-{NN}`; regex `^S(\d{1,2}|A[1-4]|B)-[A-Z]{2,6}-\d{2}$`
- Section ∈ 0–11, A1–A4 (Appendix A tables), B (Appendix B)
- Fixed domain codes:
  - Non-§4: S0-FM (front matter), S1-LOG, S2-COH, S3-DEC, S5-REC, S6-QA, S7-TRK, S8-PRK,
    S9-GUI, S10-OPT, S11-LIM, SA1-LOG, SA2-COH, SA3-DEC, SA4-TRK, SB-SOP
  - §4 manual domains: DXDT (Cancer Diagnosis Date), SRC (Source), DX (Cancer Diagnosis),
    INS (Insurance), ADI, TRT (Treatment Window), REL (Initial treatment vs relapse),
    DTH (Death), SRV (Survivorship encounters), DIST (Distance), CMNT (Amy's Word comments)
  - §4 repo-only domains (Origin = REPO-ONLY): SHS, CHM, NRM, REG, EPI, ANT, CBC, RUR, SDI,
    DOI, CLS, PDE
- Allocation: IDs are assigned once, in manual document order, and written to the **ID Registry**
  section of the map. Later additions take the next unused NN in that section-domain. IDs are
  never regenerated from row order, never reused, never renumbered.
- Reserved: `S4-CMNT-01` = c0, `S4-CMNT-02` = c1. The in-body Insurance confirm line gets a normal
  `S4-INS-NN`.

## Main table columns (also used by the AM-MAP-02 table)

| ID | Origin | AM Section | Domain | Item | Manual Lines | Manual Text | Status | Evidence Type | Repo Source | What the Source Shows | Lead | Decision ID | Notes |

- Origin: `MANUAL` or `REPO-ONLY`
- Manual Lines: line range in `AnalyticManual_2026.01.30.md` (e.g., `L82-L88`); blank for REPO-ONLY
- Manual Text: verbatim; newlines written as `<br>`, pipes escaped as `\|`; never edited after T1
- Lead: `L1`–`L9` where applicable, else blank

## Decision table columns

| Decision ID | Original ID | Decision Text | Raised By | Decided By | Date | Source File | Map Row(s) | Status | Notes |

## Markdown table rules (for the exporter to parse reliably)

One row per line; no line breaks inside a cell; `|` escaped as `\|`; empty cells are written as
`—`; each table is preceded by a level-2 heading that the exporter keys on
(`## Main Map`, `## AM-MAP-02: Repo Domains Not in Manual`, `## AM-MAP-03: Team Decisions`,
`## Coverage`, `## ID Registry`).
