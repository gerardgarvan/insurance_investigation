    - Input: a character vector of already-normalized 5-digit ZIP5 strings (may contain NA).
    - Returns TRUE for: "00000", "99999", and any other single-repeated-digit ZIP5 ("11111", "22222", ..., "88888") -- one regex covers all of these: ^(\d)\1{4}$
    - Returns FALSE for genuine ZIP5 values (e.g., "32611", "90210").
    - Returns NA for NA input (do not coerce NA to FALSE -- a missing ZIP5 is not "not sentinel", it's simply not evaluable; callers filter NA separately before calling this).
  </behavior>
  <action>
Add this function to R/utils/utils_address.R, placed after normalize_zip5_raw() and before get_zip9_at_date(), with a comment block matching the file's existing style:

    # Sentinel/placeholder ZIP5 filter (Pitfall 2, Phase 139): 00000, 99999, and any
    # other single-repeated-digit ZIP5 are known placeholder/data-quality artifacts,
    # not real addresses. Applied by callers (e.g. R/115) BEFORE counting ZIP
    # transitions, so placeholder values don't inflate change counts. NOT called by
    # get_zip9_at_date() itself -- that function is Out of Scope for modification
    # in Phase 139; sentinel filtering is applied by callers on its output/inputs.
    is_sentinel_zip5 <- function(zip5) {
      str_detect(zip5, "^(\\d)\\1{4}$")
    }

Also update the file's header comment block (Outputs section) to mention is_sentinel_zip5() alongside the existing three normalize functions. Do not change get_zip9_at_date() -- it must remain byte-for-byte unchanged.
