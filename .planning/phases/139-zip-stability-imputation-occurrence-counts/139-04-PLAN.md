Encounter-level waterfall, built directly from Plan 03's scenario_assigned column (already an

cumulative count over its factor levels in order):

    waterfall_encounter <- encounter_zip %>%
      count(scenario_assigned) %>%
      mutate(scenario_assigned = factor(scenario_assigned,
               levels = c("already_has_zip9", "S1", "S2", "S3", "unresolvable"))) %>%
      arrange(scenario_assigned) %>%
      mutate(cumulative_n = cumsum(n), cumulative_pct = round(100 * cumulative_n / sum(n), 1))

Patient-level waterfall: for each patient, the "furthest" resolved scenario across all their
encounters, in the SAME priority order (a patient counts as "already_has_zip9" if ANY encounter
already has one; else "S1" if any encounter resolves via S1; and so on down to "unresolvable"
only if EVERY encounter is unresolvable) -- this differs from Plan 03's per-encounter patient
"presence" reporting (which allowed a patient to appear under multiple scenarios); the waterfall
needs one mutually-exclusive bucket per patient so the cumulative sum reconciles to the full
patient count. Implement via group_by(ID) + slice_min on a numeric priority rank matching the
factor level order, or an equivalent min-priority selection.

C-02 reconciliation: separately from the encounter-and-scenario-based waterfall above, compute
the STRICTER address-history-wide "no usable ZIP5 anywhere" patient count directly from Plan 01's
addr_coal (not from encounter_zip): a patient qualifies if EVERY row for that ID in addr_coal (the
full universe of their address-history records, before Part B's encounter-level scenario logic
even applies) has zip5_coalesced NA. This is the number CONTEXT.md's C-02 says should land at or
near 26.

    n_patients_no_zip5_ever <- addr_coal %>%
      group_by(ID) %>%
      summarise(all_na_zip5 = all(is.na(zip5_coalesced)), .groups = "drop") %>%
      summarise(n = sum(all_na_zip5)) %>%
      pull(n)

    C02_EXPECTED <- 26L
    C02_TOLERANCE <- 5L   # generous tolerance since the exact patient universe (e.g. cohort filter
                          # applied vs not) may shift this slightly without indicating a real bug;
                          # document this choice in the KEY sheet as Claude's Discretion
    c02_reconciled <- abs(n_patients_no_zip5_ever - C02_EXPECTED) <= C02_TOLERANCE

    if (!c02_reconciled) {
      message(glue(
        "\n*** C-02 RECONCILIATION FAILURE ***\n",
        "Expected ~{C02_EXPECTED} patients with no usable ZIP5 anywhere in their address history ",
        "(per team meeting notes). Computed: {n_patients_no_zip5_ever}.\n",
        "Per 139-CONTEXT.md: 'If it does not [reconcile], stop and investigate before delivering.'\n",
        "A materially higher number means the ZIP5-coalescing fix is not reaching the raw ZIP5 ",
        "values correctly, and every downstream count in this deliverable may be wrong.\n",
        "*** DO NOT SHIP output/{basename(OUTPUT_XLSX)} TO ERIN/AMY UNTIL THIS IS RESOLVED ***\n"
      ))
    } else {
      message(glue("C-02 reconciliation OK: {n_patients_no_zip5_ever} patients with no usable ZIP5 ever (expected ~{C02_EXPECTED})"))
    }
