<objective>
Remove the stray bare `n` token that an editor left glued onto the section-divider comment immediately after `source("R/00_config.R")` in four scripts: R/74, R/81, R/82, R/83 (one occurrence each). This is part of Phase 132 (Crash Fixes) — see `.planning/ROADMAP.md` Phase 132 and `.planning/REQUIREMENTS.md` CRASH-01.

Purpose: A code review flagged these lines as a crash risk (`object 'n' not found`). Empirical verification during planning (see `<context>` below) found that in THIS codebase's current state, the bare `n` does not actually throw that error locally — `R/00_config.R` transitively attaches `dplyr` (via `R/utils/utils_duckdb.R`), and `dplyr` exports a function object named `n` (used inside `dplyr::n()` data-masking contexts), so the bare `n` resolves to that function and gets silently auto-printed to console when the script is run directly via `Rscript`. This is still a genuine editor artifact that must be removed — it is dead/accidental code with an ugly side effect (dumping a function definition into script output), not intentional code. The fix (delete the token) is unaffected by this finding; only the verification method is informed by it.

Output: Four scripts with the stray `n` removed, each script's `# ===...` divider comment left intact on its own line.
</objective>
