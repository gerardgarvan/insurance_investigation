### Header parsing: exact pattern

`parse_script_header()` (lines 45–131):

1. Finds `header_start` = first line matching `^#\s*=+` (opening `===` banner).
2. Finds `header_end` = **third** line matching `^#\s*=+`. If fewer than three
   such lines exist, falls back to the first non-comment line after `header_start`.
3. Extracts lines `[header_start:header_end]` as the "header block."
4. For each of `Purpose`, `Inputs`, `Outputs`, `Dependencies`, `Requirements`,
   searches within the header block for:
   ```r
   pattern <- glue("^#\\s*{field_name}:\\s*(.*)$")
   ```
   capturing text after the colon on the first matching line.
5. Collects multi-line continuation lines: any subsequent comment line matching
   `^#\s{2,}` that does NOT start with another field keyword.
6. If no `header_start` is found, all five fields return `"Not documented"`.

**Why "Not documented" appears for every script in the June 2026 manual:**

The pattern finds the opening `===` banner as match 1 and the closing `===` banner
as match 2. The *third* `===` match is the section header on the first real code
section (e.g., `# SECTION 1: SETUP`). The "header block" is therefore
`lines[header_start : third_===_line]`, which spans the full comment header
exactly — this part works correctly.

The actual failure is that the June 2026 manual was generated against an older
codebase where most scripts had a compressed single-line header block format
(`# Script: ... # Purpose: ...` on the same line) or no structured header at all.
The current codebase already has the five-field format in the majority of scripts
(see § Inventory below). The "Not documented" cells in the published manual reflect
the state of the scripts at generation time, not a defect in the regex.

### Classification criteria

- **PARSEABLE:** Has an opening `# ==...==` banner, one or more of the five
  labelled fields (`Purpose:`, `Inputs:`, `Outputs:`, `Dependencies:`,
  `Requirements:`), and a closing `# ==...==` before the first code section.
  R/89's `parse_script_header()` will return non-"Not documented" values for at
  least Purpose, Inputs, and Outputs.
- **USABLE:** Has a clear prose header describing purpose / inputs / outputs in a
  consistent format, but not in the five-field banner format. R/89 would return
  "Not documented" but the content is recoverable with modest parser changes.
- **NONE:** No meaningful header (bare shebang, one-line comment, or only a
  section-title comment).

## Header spec

Chosen approach: **(a) teach R/89 to read the dominant existing format.**

The spec R/89 must parse (the format already present in ~100% of production scripts):

```
# ==============================================================================
# NN_script_name.R -- One-line description
# ==============================================================================
# [optional: audit note or brief annotation line(s)]
#
# Purpose:
#   Free text. May span multiple continuation lines (each starting with #   or #  ).
#
# Inputs:
#   Free text or bullet list. Same continuation rule.
#
# Outputs:
#   Free text or bullet list. Same continuation rule.
#
# Dependencies:
#   Free text. Same continuation rule.
#
# Requirements:
#   Free text. Same continuation rule.
#
# ==============================================================================
```

**Parser rules (what R/89 should implement):**

1. Opening banner: first line matching `^#\s*=+` (at least 3 `=`).
2. Field detection: `^#\s*(Purpose|Inputs|Outputs|Dependencies|Requirements):\s*(.*)$`
3. Continuation: any subsequent line matching `^#\s{1,}` that does NOT start
   a new field keyword and does NOT match `^#\s*=+`.
4. Header ends at the second `^#\s*=+` match after `header_start`, OR at the
   first non-comment, non-blank line, whichever comes first.
5. USABLE scripts that lack the banner but have clear inline prose: add a
   `Purpose:` line extracted from the first comment paragraph. These 7 scripts
   should receive a banner header when touched next (tracked in § Known Stubs).

**Key change from current R/89 implementation:**
Current code uses the **third** `===` match as `header_end`, which picks up the
first section banner inside the script body. The corrected implementation uses
the **second** `===` match (the closing header banner) as `header_end`. This is
the main bug causing "Not documented" for scripts whose opening and closing banners
are the first two `===` lines (the third `===` is then `# SECTION 1: SETUP`
or similar, which may come before or after the closing banner depending on header
length).

Actually, re-reading the code: scripts like R/60 have the pattern:

```
Line 1:  # ============... (header_start = match 1)
...
Line N:  # ============... (match 2 = closing banner)
Line N+1: # (blank or section comment)
...
Line M:  # ============ SECTION 1 (match 3 = header_end)
```

For these scripts, `header_lines = lines[1:M]`, which includes the entire header.
The field patterns then successfully find `Purpose:` etc. within that range.

The June 2026 manual's "Not documented" cells more likely reflect that those
scripts genuinely lacked five-field headers at generation time, and the pipeline
has since been updated. The corrected approach (option a) proceeds as planned.
